## 1. 产品概述

系统为添加在 Pixel 上的 OpenAI 账号建立本地监控。它按配置周期读取账号的 seven_day 用量，将原始响应落盘并将结构化数据写入 SQLite，计算额度估算值。当估算额度异常下降或单位增量消耗低于阈值时，系统发送邮件告警，并可按策略暂停异常账号的调度。

系统输出的是基于 usage 数据的估算结果，不替代 Pixel 的账单或官方额度结算。

## 2. 产品目标

### 必须达到

- 管理员能够安全登录、修改默认凭据和管理监控配置。
- 系统能够周期性获取所有启用监控账号的 seven_day 数据，并保留可追溯的原始响应。
- 每条采样都能得到两个额度指标或明确的不可计算原因、趋势和阈值状态。
- 同一本地管理员可接入多个 Pixel 租户及每租户的多个管理账号。
- 额度异常能够通过邮件通知；账号级策略启用时能够调用 Pixel API 暂停调度。
- 密钥、Token、Pixel 凭据和 SMTP 凭据不以明文存储或写入日志。
- 支持在经过验收的 DBX 本地连接中凭数据库密码直接读取表结构与普通业务数据；应用层加密的机密字段仍保持密文。
- Windows 测试包可运行；架构为后续 Linux + Nginx 部署保留空间。

### 不在本期范围

- Pixel 账单结算、充值或额度购买。
- 修改 Pixel 的账号密码、API Key 或模型配置。
- 本地应用的多组织权限隔离、多人协作、细粒度角色权限和移动端 App；连接多个上游 Pixel 租户属于本期范围。
- 替代 Pixel 管理后台的全部账号管理能力。

## 3. 角色与权限

首版只有一个本地管理员角色。管理员可以查看和修改所有系统配置、账号策略、密钥和审计记录。未登录用户只能访问登录页。密钥查看和轮换还需要分别进行操作级密码验证。

术语分为三级：Pixel 租户是配置的上游连接范围；Pixel 管理账号是用于登录和获取 Token 的身份；监控账号是账号列表中的 OpenAI account_id。不同租户的同号 account_id 不能混用，管理账号登录名也不能脱离租户单独作为全局标识。

## 4. 核心术语和计算口径

### 4.1 原始字段

从 seven_day 保存 utilization、requests、tokens、cost、user_cost；同时保存租户、管理账号、监控账号引用，请求时间、上游 updated_at（若有）、source、timezone、原始文件路径和处理状态。

关联 API 文档只给出部分结构体：cost/user_cost 对应 SevenDay.WindowStats；requests/tokens 的具体 JSON 路径、空值行为需用脱敏响应补齐，不能猜测字段后声明已确认。

### 4.2 额度指标

设当前采样为 N，上一条同一监控账号按采集顺序成功入库的采样为 P。沿用 README 原式，utilization 使用百分数数值；不会擅自先除以 100。

1. credit_limit_by_cost = cost / utilization。分母为 0 时记 -999。
2. credit_limit_by_delta = (cost(N) - cost(P)) / (utilization(N) - utilization(P))。分母为 0 或无前一采样时记 -999。

保存原始精度，比较阈值前不按展示精度舍入；页面默认保留两位小数。-999 是不可计算标记，另存无前值、分母为零等原因。字段缺失或解析失败不能伪装成正常零值；seven_day 回退或重置的处理见 R1。

### 4.3 utilization 单位和数值样例

上游值 57 表示 57%；从 57 到 58 是增加 1 个百分点。保存原始百分数，告警计数也使用该口径。

| 样本 | cost | utilization | 按 README 原式的结果 |
|---|---|---|---|
| P | 171000 | 57 | credit_limit_by_cost = 3000 |
| N | 174000 | 58 | credit_limit_by_cost = 3000；credit_limit_by_delta = 3000 |

该结果量纲是 cost 单位/百分点。如果业务实际要表达 100% 的总额度，两式需乘以 100，示例变成 300000；不能仅转换 utilization 就默认沿用原有阈值含义。默认三档 3000/2400/1600 保留，R1 核验业务预期，而不是重新询问已经确认的上游单位。

### 4.4 credit_limit_by_cost 趋势

variation_pct = (new_credit_limit_by_cost / last_credit_limit_by_cost) - 1。

- variation_pct < -告警阈值：下降超过阈值，触发异常。
- variation_pct >= 告警阈值：上升。
- 其余范围：基本持平。

默认阈值为 5%，可配置。严格遵循 README 的小于号，恰好下降 5% 不触发；当前或前值为 -999、前值为 0 或不存在时跳过并记录原因。恢复判定的“上升”是否复用展示档位尚未确认，不能直接当作上涨至少 5%。

### 4.5 credit_limit_by_delta 档位与暂停

默认 high=3000、medium=2400、low=1600，可配置，满足 high > medium > low。按 README，自动暂停默认开启；账号未设置覆盖值时使用全局默认策略。

| 指标范围 | 档位与动作 |
|---|---|
| 大于等于 high | 正常 |
| 大于等于 medium 且小于 high | 观察 |
| 大于等于 low 且小于 medium | 警告 |
| 小于 low | 严重异常，检查自动暂停策略 |
| 等于 -999 | 跳过比较，不触发暂停；显示不可计算原因 |

展示指标与三个阈值的差值。只有有效 delta < low 且全局与账号策略均允许时，才自动暂停；cost 下降本身不是自动暂停条件。每条有效 delta 独立检查，不必先有 cost 告警或等完整 1% 观察结束。

按 README，全局关闭时账号级配置不生效；当前文档按全局阈值继续比较和告警、只禁用自动暂停动作。若关闭仅应影响账号级暂停开关而不影响账号级阈值，需在评审中指出该区别，见 11.2。

### 4.6 异常采样、两次跳变与恢复

每个监控账号独立维护异常事件：

1. 首次 cost 下降超过阈值，建立事件并发送首次预警，切换告警采样间隔（默认 30 秒）；计数器置 0。同一未恢复事件不反复启动加速。
2. 未自动暂停时，utilization 相比上一采样第一次增加 1，计数为 1，保存该边界的 utilization、cost、采样时间，作为完整区间起点。
3. 下一次再增加 1，计数为 2，才完成加速后的一个完整百分点。例如 57 触发，后续 57 不计数，58 是第一次边界，59 是第二次边界；完整区间是 58 到 59。
4. 完整区间仍异常时，提示建议立即人工暂停、恢复普通间隔（默认 60 秒）；确认邮件数量与“仍异常”的计算方式见 R2。额度未恢复前不重复加速。
5. 自动暂停成功后，立即恢复普通间隔。Pixel 停止调度不等于停止本地监控；暂停失败或结果未知不能标记成功。
6. README 指定恢复依据为 cost 指标上升、delta 指标大于中档。建议解释为同一条有效采样上 cost 指标比前值增加且 delta > medium，见 R2；恢复后才允许新一轮异常与加速。
7. 恢复事件不自动开启 Pixel 调度；如需恢复调度，由管理员确认后操作。

正常逐条 delta 仍按 4.2 使用上一条采样；完整区间的观察值如果需要，必须单独命名，不能偷偷替换逐条 delta。建议持久化事件 ID、间隔、计数器、边界样本、恢复锁和动作状态，使重启不会重复开启同轮加速。跨多个百分点、回退、长期不跳变及提前恢复的边界见第 11 节。

## 5. 功能需求

### 5.1 本地登录和账号安全

| 编号 | 需求 | 验收要点 |
|---|---|---|
| AUTH-01 | Windows 与 Linux 首次初始化均提供默认账号 fuck_openai 和默认密码 pixel_test。 | 首次登录强制改密；重启不重置管理员凭据。 |
| AUTH-02 | 新密码不能等于默认密码，并满足配置的最小长度和复杂度。 | 使用默认密码提交修改时被拒绝，并给出明确原因。 |
| AUTH-03 | 初始化完成后每次登录都检查密码是否仍为默认值。 | 提示“非正常使用情况，你的密码与初始密码一致，存在安全隐患，请立即修改！”；建议继续限制到改密页，见 11.2。 |
| AUTH-04 | 只有已修改默认密码后，管理员才能修改登录账号。修改账号前必须重新验证当前密码。 | 默认密码状态下修改账号被拒绝；密码已修改且验证通过后才能保存。 |
| AUTH-05 | 会话具备过期、退出和失败登录限制。 | 过期后回到登录页；失败次数和锁定状态可在审计记录中查询。 |

### 5.2 密钥和机密信息

| 编号 | 需求 | 验收要点 |
|---|---|---|
| SEC-01 | 首次启动生成两个 16 字节随机值，并编码为 32 个十六进制字符：数据库加密密钥、机密信息加密密钥。 | 只在首次初始化生成；重启不重复覆盖；值不写入日志。 |
| SEC-02 | 管理员输入密码后可分别查看两个密钥。查看每个密钥都要单独验证。 | 验证失败不显示任何密钥；成功后仅在受控页面短时显示。 |
| SEC-03 | 管理员输入密码后可分别轮换两个密钥。 | 保存前显示影响范围和预计暂停服务提示；取消不会改变任何密钥。 |
| SEC-04 | 推荐 SQLCipher 4 默认格式；两个密钥独立轮换，任一轮换期间暂停对外数据库服务。机密信息轮换使用旧密钥解密、用新密钥重加密全部受保护记录。 | 提示“更换密钥会暂停数据库服务，轮换加密需要时间”；进度可查、失败可恢复。内部迁移访问不属于对外数据库服务。 |
| SEC-05 | 数据库密钥轮换时继续抓取上游原始 JSON，但暂停 ETL 入库；轮换成功后按时间顺序补偿入库。 | 原始文件不丢失；轮换结束后补偿任务可重试且不重复生成采样。 |
| SEC-06 | 用户取得数据库口令后，可用已验收的 DBX 本地连接打开加密数据库或一致性加密备份，不需要先导出明文库。 | 正确口令可读普通业务数据，错误口令被拒绝；数据库轮换后新口令可用、旧口令对新文件失效；记录客户端版本和加密参数。 |

数据库口令、Web 登录密码和机密信息密钥是三个不同概念。建议将数据库密钥生成的 32 个 hex 字符按原样作为文本口令交给 SQLCipher，通过其密钥派生机制处理；DBX 输入相同文本。不得把这 32 个字符当作 SQLCipher 的 32 字节原始密钥（原始密钥模式要求 64 个 hex 字符）。相关依据见架构第 6.1/9 节。

打开数据库只解开文件层：usage 等普通字段可读，第二密钥保护的 Token/密码等字段仍为密文。独立机密信息密钥轮换不能改变数据库口令。

本地登录密码继续要求不可逆校验。建议将带随机盐的密码哈希再用机密信息密钥加密，使哈希本身可重新加密；不保存可还原的本地明文密码，也不直接把可轮换密钥当作密码盐。该建议及启动密钥保管方式见 R3。

### 5.3 Pixel 账号和数据采集

| 编号 | 需求 | 验收要点 |
|---|---|---|
| DATA-01 | 配置多个 Pixel 租户；每个租户支持多个管理账号，凭据加密保存并完成登录、Token 保存和失效重登。 | Token 不出现在页面和日志；401 能定位到租户和管理账号并提示重新认证。 |
| DATA-02 | 使用 Pixel 账号列表接口同步 `account_id`、名称、平台、等级、状态、并发等基础信息，本期只纳入 `platform=openai` 的账号。 | 账号列表可手动刷新；已删除或失效账号标记为不可用而不删除历史采样。 |
| DATA-03 | 对每个启用监控账号按正常采样间隔请求 usage 接口：默认 60 秒，可配置。 | 每次独立采集产生一条采样；同一原始文件重试 ETL 不重复入库。不同请求不能因 updated_at 或 utilization 相同而合并；单账号失败不影响其他账号。 |
| DATA-04 | usage 请求默认使用 source=local、timezone=Asia/Shanghai，并允许在配置中调整时区。 | 实际请求参数和响应时间写入同步日志。 |
| DATA-05 | 每次响应先以完整 JSON 落盘，再解析并写入数据库。 | 原始文件与数据库采样可互相定位；解析失败保留原始文件并显示失败原因。 |

### 5.4 原始数据和缓存

| 编号 | 需求 | 验收要点 |
|---|---|---|
| RAW-01 | 原始文件按类型、账号和时间组织，文件名包含采样时间和参数摘要。 | 文件可从采样详情下载或定位；路径不包含未经清洗的邮箱特殊字符。 |
| RAW-02 | 管理员可配置原始文件保留天数。数据库成功抽取后，过期的原始文件可删除。 | 清理任务只删除已成功入库且超过保留期的文件。 |
| RAW-03 | 管理员可配置最大缓存字节数；超限时从最老的已成功抽取文件开始清理，即使尚未超过保留天数。 | 显示实际字节数与可读单位；只删除已抽取文件，不删除待抽取或解析失败记录。无可清理文件时见 11.2。 |
| RAW-04 | 清理失败不影响下一次采样，并记录原因。 | 磁盘权限、文件占用和空间不足都能在任务日志中识别。 |

### 5.5 异常、告警和调度控制

| 编号 | 需求 | 验收要点 |
|---|---|---|
| ALERT-01 | 新采样入库后计算 credit_limit_by_cost 趋势。下降严格超过默认 5% 且不属于同一未恢复异常时建立事件并发送首次预警。 | 邮件包含租户、管理账号、监控账号、时间、指标变化及受权限控制的详情/原始记录链接。 |
| ALERT-02 | 首次额度异常后将该账号采样间隔切换为默认 30 秒的告警间隔，告警间隔可配置；自动暂停成功或加速窗口仍异常完成后恢复默认 60 秒间隔。 | 下一次调度使用新间隔；调度器显示账号当前间隔、异常事件、加速窗口和恢复原因。 |
| ALERT-03 | 新采样入库后比较 credit_limit_by_delta 与三档阈值。-999 时跳过。 | 页面展示档位和差值；跳过原因可查。 |
| ALERT-04 | 全局配置控制是否允许自动暂停；全局开启时账号级配置可以设置阈值和是否自动暂停。 | 全局关闭时任何账号都不自动暂停且账号级设置不生效；全局开启时账号级关闭可阻止该账号自动暂停。 |
| ALERT-05 | delta < low 且策略允许时调用 PUT /api/v1/accounts/{account_id}，请求体为 schedulable=false；管理员确认后的恢复操作使用 true。 | 按接口契约确认成功才标记已暂停并恢复普通采样；失败记录错误和重试。额度恢复不自动调用 true。 |
| ALERT-06 | 记录告警、邮件发送和调度变更的完整审计。 | 审计包含触发采样、规则版本、请求结果、重试和最终状态。 |
| ALERT-07 | 同一异常通知不能因快速采样重复发送。 | 成功发送后停止重复投递；首次预警与完整区间确认是否各发一封待 R2 决定，不擅自取消任一 README 要求。 |
| ALERT-08 | Web 支持管理账号默认收件人及其下属监控账号的独立收件人。 | 不同管理账号、同一管理账号下不同 account 均可发给不同的人；继承与覆盖建议见 11.2。 |

## 6. 核心流程

### 6.1 首次启动与登录

1. 首次启动生成两个随机密钥并按批准方案保管，再按通过兼容验收的加密方案建库；当前建议为 SQLCipher 4 默认格式。
2. 创建默认本地管理员。
3. 管理员使用默认凭据登录。
4. 系统强制进入修改密码页；修改成功后才进入仪表盘。
5. 管理员配置 Pixel 租户、管理账号凭据、SMTP、分账号通知人和采集策略。

### 6.2 一次采样

1. 调度器选择到期且启用监控的 OpenAI 账号；Pixel 调度暂停不等于本地监控暂停。
2. 使用有效 Pixel Token 请求 usage。
3. 将完整响应写入原始 JSON 文件并记录文件状态。
4. 解析 seven_day 字段，获取上一条成功采样。
5. 计算两个额度指标、趋势和 delta 档位。
6. 在一个数据库事务中写入采样、规则结果和同步日志。
7. 按告警策略发送邮件；按自动暂停策略调用 Pixel PUT API。
8. 更新账号下一次采样时间，并执行可异步运行的原始文件清理。

### 6.3 密钥轮换

1. 管理员通过密码验证并确认影响范围。
2. 准备运行所需的采集配置与凭据快照，进入维护状态、排空数据库操作，暂停对外数据库读写及 ETL。
3. 上游抓取继续运行，原始 JSON 继续落盘。
4. 完成数据库密钥切换或全部机密字段重加密。
5. 验证使用新密钥可读写、存量数据可解密、事务一致，再完成密钥版本切换。
6. 恢复 ETL，按原始文件时间顺序补偿入库。
7. 轮换失败时恢复旧状态并显示可操作的重试信息。

## 7. 数据要求

以下为待实现的逻辑集合，不表示已有表或迁移：

- app_users：本地账号、密码校验材料（强哈希，额外加密封装见 R3）、初始化状态、失败次数。
- app_settings：采样、阈值、SMTP、时区、保留策略、缓存字节上限、全局开关。
- pixel_tenants：本地租户标识、展示名、上游连接配置。
- pixel_admin_accounts：所属租户、加密登录账号/密码、认证状态、默认通知人。
- pixel_sessions：所属管理账号、加密 Token/Cookie、实际可获取的有效期信息。
- monitored_accounts：所属租户、account_id、可用管理账号关系、基础信息、阈值/自动暂停/收件人覆盖。
- usage_samples：采集唯一标识、所属监控账号、原始字段、两个指标、前值引用、趋势、档位、采集时间、质量状态。
- raw_files：采集标识、归属、路径、字节大小、校验值、是否抽取、保留状态；数据库离线时还需可独立恢复的文件元数据。
- alert_events：触发样本、规则版本、前后值、阶段、计数器、边界样本、当前间隔、恢复锁、结束原因；阶段细节依 R2 定稿。
- email_deliveries：事件/通知类型、收件人快照、模板版本、结果、重试和时间。
- schedule_actions：所属账号、暂停/恢复请求、结果、最终状态、重试。
- job_runs：采集、ETL、清理、轮换任务的开始、结束、状态和错误。
- audit_logs：登录、配置、密钥操作（不含密钥值）、告警和调度操作。

时间统一以 UTC 存储，页面按配置时区展示。跨租户标识、同租户多管理账号交叉可见及幂等边界见架构文档。

## 8. 外部接口

### Pixel 接口

以关联项目接口文档为准：

- 登录页和 POST /api/v1/auth/login。
- GET /api/v1/accounts 获取账号列表。
- GET /api/v1/accounts/{account_id}/usage?source=local&timezone=Asia%2FShanghai 获取用量。
- PUT /api/v1/accounts/{account_id}，请求体 {schedulable:false/true} 控制调度。

接口 host、port、超时和时区不得硬编码在业务逻辑中。网络失败、401、业务错误和格式错误必须区分记录。

### 邮件接口

首版采用 SMTP。收件人由 Web 页面配置；服务器、端口、TLS、发件人和凭据建议在同一页面输入，凭据按机密信息保护。测试邮件必须使用同一套连接配置，凭据录入方式见 11.2。

## 9. 非功能要求

- 安全：密码使用强哈希；会话 Cookie 设置 HttpOnly、Secure（启用 HTTPS 时）和 SameSite；所有敏感配置加密；页面和日志不显示 Token、密码或完整密钥。唯一密钥展示例外是管理员重新验证后的专用短时查看入口。
- 一致性：原始文件状态与数据库采样状态可追溯；同一采样重试不产生重复有效记录。
- 隔离性：单账号网络或解析失败不能阻断其他账号；数据库写入使用事务。
- 可恢复性：任务失败可重试；服务重启后恢复未完成任务；密钥轮换具备失败恢复状态。
- 性能：在配置采样间隔内完成一轮账号采样；并发度可配置且不压垮 Pixel API。
- 可观测性：所有后台任务都有状态、耗时、错误和最近成功时间。
- 部署：Windows 首版提供可运行包；后续 Linux 以单服务运行，由 Nginx 提供外部访问和 TLS。

## 10. 验收标准

1. Windows 与 Linux 首次登录均不能绕过强制改密；修改后才能进入仪表盘。
2. 修改后的账号密码可正常登录；默认密码登录会产生安全提示。
3. 给定一组 seven_day 样例，系统能得到正确的两个指标；分母为 0 时准确保存 -999。
4. 连续两条采样能得到正确的 credit_limit_by_delta；无前值或用量未变化时跳过比较。
5. cost 指标下降严格超过阈值时首次预警并加速；恰好下降 5% 不触发；同一未恢复事件不重复加速或重发已成功发送的通知。
6. credit_limit_by_delta 低于最低阈值时，全局和账号策略组合结果正确；关闭自动暂停时不调用暂停 API。
7. 暂停 API 返回失败时，账号不会显示为已暂停，系统会重试并记录错误。
8. 密钥轮换期间原始 JSON 持续产生、ETL 暂停；轮换完成后数据可补偿入库。
9. 原始文件清理只删除已成功入库且满足保留时间或缓存上限的文件。
10. Windows 测试包重启后配置、采样、事件阶段、日志和密钥状态仍可恢复。
11. 多租户及多个管理账号独立认证；非 OpenAI 账号不采样；同号 account_id 不跨租户串数据或串暂停目标。
12. 57 触发、58 首次边界、59 第二次边界时，完整观察区间为 58 到 59；确认邮件与恢复断言按 R2 定稿。
13. 自动暂停成功后继续普通采样；失败不伪造成功，额度恢复不自动开启 Pixel 调度。
14. 管理账号及监控账号的收件人路由正确，通知不会发送给其他账号的专属收件人。
15. 两个密钥均为 16 随机字节/32 hex 字符、可独立轮换；数据库和应用层机密都有恢复验证。
16. 应用创建的库在 DBX 本地连接中输入数据库口令即可读表和业务记录；用带 SQLCipher 支持的 DB Browser 交叉验证。两者均记录实际版本，不把文档支持当成实测通过。
17. 数据库轮换后新口令可以在外部客户端重新打开，旧口令不能打开轮换后的文件；机密字段仍为密文。Linux 生成的加密一致性备份复制到 Windows 后同样通过本地打开验证。

## 11. 待确认事项

### 11.1 三组需要定稿的产品决定

旧版十项问题的明确答案已纳入 1.1，以下只讨论剩余边界。建议均不等于批准。

| 编号 | 需要确认的内容 | 建议及影响 |
|---|---|---|
| R1 计算量纲与回退 | cost=171000、utilization=57 时，预期结果为 3000 还是 300000？三档阈值对应哪种量纲？seven_day 用量/cost 回退或重置如何处理？ | 建议沿用百分数直接相除，结果 3000；选择总额度时需重新确认阈值。回退建议保存样本和原因、重建基线，跳过跨窗口 delta/趋势/自动动作，避免负差分误停。 |
| R2 异常生命周期 | 原需求第 17 条要求首次邮件，确认值第 2 条要求完整 1% 后确认邮件，第 3 条又要求一个事件一封：整轮一封，还是首次/确认各一封？完整区间“仍异常”按哪个指标/阈值？恢复是否要求 cost 任意正增长且 delta > medium 在同条样本同时成立？ | 建议两个通知阶段各最多一封；完整区间另算观察值 (cost_end-cost_start)/(util_end-util_start)，低于 low 才确认严重异常，不替换逐条 delta。恢复建议两条件同条成立且不要求涨 5%。以上均待确认。 |
| R3 密钥保管与访问方式 | 是否允许重启后无人值守解锁？启动密钥如何保管和备份？是否接受本地密码强哈希后再加密哈希？第三方访问需不需要直接通过 SSH 打开服务器文件？ | 推荐 SQLCipher 4 默认格式及文本口令；具体非 Go 绑定交由技术验证。DBX 本地读取作为验收目标；其远程 SQLite SSH Worker v1 的官方说明不支持 SQLCipher，不承诺该路径，推荐先取得加密一致性备份本地读取。无人值守密钥保管和跨机器恢复仍需定稿。 |

R2 还需确定退出边界：完整区间已结束但既未严重异常也未满足恢复、长期不发生第二次跳变、自动暂停已启用但一直未低于 low 时如何退出加速。建议完整区间结束后回普通间隔，未达恢复则保留事件锁；提前恢复则结束加速。停滞超时值尚无确认，不自行写死。

### 11.2 随需求评审接受或调整的实现建议

- 收件人：账号显式列表覆盖管理账号默认列表，不自动合并；未配置时继承，最终为空时显示“通知未配置”。SMTP 和 Pixel 凭据建议在本地 Web 输入；README 未逐项回答凭据录入方式。
- 账号交叉可见：建议同租户相同 account_id 合并监控、显式选择负责采集/暂停的管理账号；先用样例核实租户内 ID 的共享语义。
- 跳变异常：一次跨多个百分点、回退或采集中断不能声称已观察到完整相邻边界；建议重新等待可识别区间并记录原因。
- 缓存全部未抽取：禁止删除待处理数据；无法容纳新文件时暂停新抓取、展示积压/空间告警，腾出空间后恢复。“轮换期间采集继续”以可用缓存和上游认证有效为前提。
- 默认密码异常登录：建议继续限制到改密页；最小密码长度、会话过期、重试参数在实现设计中明确，不视为已有配置。
- 全局关闭的范围：当前按 README 字面解释为账号级设置整体不生效、使用全局阈值继续告警。若本意只禁用暂停动作、仍保留账号级阈值，应明确调整。
- 脱敏契约样例：补齐 usage、分页账号列表、PUT 成功/失败、认证失败；关联项目的封装行为不是本项目已实现能力。
- 实现前验证：SQLCipher 4 默认参数、口令语义、实际非 Go 绑定、事务/轮换及 Windows/Linux 打包；DBX 与 SQLCipher 版 DB Browser 的版本及本地打开能力。后端语言/框架、CPU 架构、密钥保管、备份恢复及缓存默认值尚未选定。依据和远程访问限制见架构第 6.1、8、9 节。
