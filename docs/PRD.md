## 1. 产品概述

系统为添加在 Pixel 上的 OpenAI 账号建立本地监控。它按配置周期读取账号的 seven_day 用量，将原始响应落盘并将结构化数据写入 SQLite，计算额度估算值。当估算额度异常下降或单位增量消耗低于阈值时，系统发送邮件告警，并可按策略暂停异常账号的调度。

系统输出的是基于 usage 数据的估算结果，不替代 Pixel 的账单或官方额度结算。

## 1.1 本轮确认记录

依据归档 README 的“1.0 版”确认值、“1.3-draft 版”条目，以及截至 2026-09-28 的逐项问答更新。问答明确了跨百分点计算、统一基线重置、实时 delta、数据异常邮件、阈值预设和批量修改。稳定 cost 与 delta 保持独立规则和事件；同一采样有多项**已启用**邮件提醒时，统一合并为一封“多合一提醒”。两个密钥由应用根目录 `.env` 提供；产品不实现 SSH 远程数据库访问，也不通过 Web 提供 `.env` 或数据库下载、备份和恢复。SQLCipher 4 默认文件格式与 DBX 本地打开仍是推荐基线，依据见 ARCHITECTURE.md 第 9 节。此前撤销 Go 强制依赖的决定保留；替代语言和框架尚未选定，但该选择属于需求批准后的技术设计决定，不再作为用户产品确认项。Linux 发行版/版本只用于最终封包与系统运行库兼容性验证，不阻塞前期开发。局部规则已确认不代表整体需求获准实现，评审状态见第 11 节。

## 2. 产品目标

### 必须达到

- 管理员能够安全登录、修改默认凭据和管理监控配置。
- 系统能够周期性获取所有启用监控账号的 seven_day 数据，并保留可追溯的原始响应。
- 每条采样都能得到两个实时指标或明确的不可计算原因；有效 utilization 跳变能得到相应稳定指标或明确的预热/重建基线原因。
- 同一本地管理员可接入多个 Pixel 租户及每租户的多个管理账号。
- 额度异常能够通过邮件通知；账号级策略启用时能够调用 Pixel API 暂停调度。
- Token、Pixel 凭据和 SMTP 凭据不得明文写入数据库或日志。两个根密钥按明确要求保存在本机应用根目录 `.env`，不得提交、打印或通过普通页面暴露。
- 支持在经过验收的 DBX 本地连接中凭数据库密码直接读取表结构与普通业务数据；应用层加密的机密字段仍保持密文。
- Windows 首版交付单个可直接点击运行的 `.exe`；Linux x86_64 版也交付单个可执行文件。两端首次运行均在程序文件同目录生成 `.env` 和加密数据库，其余设置通过 Web 管理并保存在数据库；Linux 后续由 Nginx 反代。
- Windows 与 Linux 均只允许通过操作系统或服务器文件管理方式取得、复制和备份 `.env` 与加密数据库；Web 不提供这两个文件的下载、导出、备份或恢复入口。完整恢复必须同时持有相互匹配的 `.env` 和一致性加密数据库文件。

### 不在本期范围

- Pixel 账单结算、充值或额度购买。
- 修改 Pixel 的账号密码、API Key 或模型配置。
- 本地应用的多组织权限隔离、多人协作、细粒度角色权限和移动端 App；连接多个上游 Pixel 租户属于本期范围。
- 替代 Pixel 管理后台的全部账号管理能力。
- SSH 隧道、远程数据库协议、通过 DBX 直接打开服务器上的活动数据库，以及由产品代替用户登录服务器下载数据库文件。
- 通过 Web 下载、导出、备份或恢复 `.env` 和数据库文件；产品不代替部署管理员保管恢复集合。

## 3. 角色与权限

首版只有一个本地管理员角色。管理员可以查看和修改所有系统配置、账号策略、密钥和审计记录。未登录用户只能访问登录页。密钥查看和轮换还需要分别进行操作级密码验证。

术语分为三级：Pixel 租户是配置的上游连接范围；Pixel 管理账号是用于登录和获取 Token 的身份；监控账号是账号列表中的 OpenAI account_id。不同租户的同号 account_id 不能混用，管理账号登录名也不能脱离租户单独作为全局标识。

## 4. 核心术语和计算口径

### 4.1 原始字段

从 seven_day 保存 utilization、requests、tokens、cost、user_cost；同时保存租户、管理账号、监控账号引用，请求时间、上游 updated_at（若有）、source、timezone、原始文件路径和处理状态。

关联 API 文档只给出部分结构体：cost/user_cost 对应 SevenDay.WindowStats；requests/tokens 的具体 JSON 路径、空值行为需用脱敏响应补齐，不能猜测字段后声明已确认。该关联文档中的 `estimated_total_quota = round(cost / utilization)` 是关联项目的旧业务算法，只能作为字段/API 参考，不能覆盖本 PRD 的四指标公式。

### 4.2 额度指标

同一监控账号按成功采集顺序处理。设当前样本为 N，紧邻前一成功样本为 O，上一次 utilization 增加时的跳变样本为 J，实时 delta 当前固定基准为 B（初始/重置记录，或最近一次跳变记录）。`utilization` 保存 0–100 的百分数数值；四项额度估算均以乘以 100 表示完整 100% 的估算额度。平台期仍可计算实时指标，稳定指标只在 utilization 增加时计算。

初始化、进程重启、utilization 回退，以及原始 cost 下降时统一重建计算基线。**重启后首条成功采样直接作为新基线，不与重启前最后一条样本比较，也不补发停机期间可能发生的回退邮件**。基线记录本身的实时 delta 为“基线建立/重置，不可计算”，不能写成数值 0。基线后的**第一次** utilization 增加（可以跨多个百分点）只记录新的跳变起点，不计算两个稳定指标；**第二次**增加起才计算两个稳定指标。平台期不计入“第几次增加”。cost 下降是否发送独立异常邮件按 4.7 判断：仅在**这一条刚从非零 utilization 重置到 0**时，cost 归零下降不发一般 cost 下降邮件；后续 `0→0` 再下降仍是新异常。

1. `credit_limit_by_cost`：第二次及以后 utilization 增加时，用**当前跳变记录**计算 `cost(N) / (utilization(N) - 1) * 100`。该口径有意偏高：即使偏高的结果仍低于警戒值，也可直接说明额度偏低。跨越多个百分点时公式不变。`utilization(N) <= 1` 或 cost 无效时不可计算。
2. `credit_limit_by_delta`：第二次及以后 utilization 增加时，用相邻两次跳变计算 `(cost(N) - cost(J)) / (utilization(N) - utilization(J)) * 100`。分母是**实际跨越的百分点数**；一次跨越 2 个百分点时除以 2，再乘以 100，不能按 1 处理。
3. `credit_limit_by_cost_real_time`：每条分母有效的采样计算 `cost(N) / utilization(N) * 100`。utilization 为 0 时不可计算。
4. `credit_limit_by_delta_real_time`：基线 B 建立后的后续采样计算 `(cost(N) - cost(B)) / D * 100`，其中 `D = utilization(N) - utilization(B)`；仅当 `D=0` 时将 D 修正为 1。B 不随每条采样更新，只在初始/重置或 utilization 增加后更新。**跳变当条先使用旧 B 计算并保存实时 delta，再把 N 更新为下一条采样的 B**；因此该条值不会被当前记录自己减成 0。

一次跨越多个百分点时仍计算稳定/实时指标，仍允许告警和自动暂停；样本、页面、邮件和审计均标记“本次采样跨越多个百分点，估算精度可能较低，建议缩短采样间隔”。基线重置后的第一次增加仍只建立起点，即使跨越多个百分点也不例外。所有稳定指标只写在实际计算的跳变采样上；平台期不得复制旧稳定值冒充新值，页面可显示最近一次稳定值及时间。

比较阈值前不按展示精度舍入；页面默认保留两位小数。数据库可继续用 -999 作为不可计算兼容值，但必须同时保存结构化原因；缺失、解析失败、基线建立和真实数值 0 必须可区分。实时指标只用于观察，不直接触发本期稳定指标邮件、采样加速、恢复或自动暂停。

### 4.3 utilization 单位和数值样例

上游值 57 表示 57%；从 57 到 58 是增加 1 个百分点。保存原始百分数，跳变识别和告警计数也使用该口径。

README 给出的实时 cost 量级样例：`cost=318.24, utilization=16` 时，`318.24 / 16 * 100 = 1989`。若 N 为 `utilization=18, cost=360` 且已完成首次跳变预热，则稳定 cost 为 `360 / (18 - 1) * 100 ≈ 2117.65`。若上一次跳变 J 为 `utilization=16, cost=318`，稳定 delta 为 `(360 - 318) / (18 - 16) * 100 = 2100`；这次跨越 2 个百分点，须附低精度提示。

实时 delta 样例：初始基准 B 为 `16% / cost=318`，平台期新样本为 `16% / cost=320`，分母 0 修正为 1，得到 200；之后跳变样本为 `18% / cost=360`，**仍用旧 B** 得到 `(360-318)/(18-16)*100=2100`，再把 `18% / 360` 更新为后续实时基准。基线记录本身不可计算，不显示 0。

### 4.4 credit_limit_by_cost 趋势

基线重置后的第一个稳定 `credit_limit_by_cost` 没有前值，只与账户当前生效预设的 `low` 比较：严格小于 `low` 就建立 cost 异常事件、发 cost 邮件并加速采样；仅凭这项 cost 结果不自动暂停 Pixel 调度。若不低于 `low`，只保存为后续比较基准。

从第二个稳定 cost 起，只比较相邻两次稳定值，不再使用 `low` 判断该指标：

`variation_pct = (new_credit_limit_by_cost / last_valid_credit_limit_by_cost) - 1`。

- variation_pct < -告警阈值：下降超过阈值，触发异常。
- variation_pct >= 告警阈值：上升。
- 其余范围：基本持平。

默认下降阈值为 5%，可配置。严格遵循小于号，恰好下降 5% 不触发；当前或前值不可计算、前值为 0 时跳过并记录原因。邮件须区分“首个稳定值低于 low”和“相对前值下降超过阈值”。cost 异常事件在后续稳定 cost 严格大于前一个稳定 cost 时恢复，不要求上涨达到 5%。实时 cost 不触发趋势告警。

### 4.5 credit_limit_by_delta 档位与暂停

内置预设默认 `high=3000、medium=2400、low=1600`，满足 `high > medium > low`。用户可创建多套命名预设；全局同一时间选一套生效预设，各账户可选一套账户预设或继承全局。账户级选择优先；未选则用全局预设。自动暂停默认开启，暂停开关仍按全局/账户优先级处理。

| 指标范围 | 档位与动作 |
|---|---|
| 大于等于 high | 正常 |
| 大于等于 medium 且小于 high | 观察 |
| 大于等于 low 且小于 medium | 警告 |
| 小于 low | 严重异常，检查自动暂停策略 |
| 不可计算 | 跳过比较，不触发暂停；显示预热或质量原因 |

展示稳定 delta 与三个生效阈值的差值。基线重置后的首次 utilization 增加只建立锚点；第二次及以后增加得到稳定 delta 后，严格低于生效 `low` 即建立 delta 异常事件；仅在全局和账户暂停策略均允许时自动暂停。稳定 cost 低于 `low`、稳定 cost 下降或实时 delta 本身都不是自动暂停条件。

delta 异常事件在后续有效稳定 delta 严格大于 medium 时恢复；等于 medium 仍未恢复。恢复只解除本地事件锁，不自动把 Pixel 调度重新开启。

全局自动暂停关闭时，任何账户都不执行自动暂停；账户级暂停偏好保留但暂不生效。账户选定的阈值预设仍用于指标档位、邮件和零利用率残留判断；全局自动暂停开关不改变预设的继承关系。

### 4.5.1 命名阈值预设与批量修改

- 预设库可保存多套有名称的 `high/medium/low`。全局始终选择一套生效；每个账户同一时刻最多选择一套账户预设，或选择继承全局。切换预设或修改被引用预设的数值，从**下一条成功采样**开始影响所有相关账户的档位、首个稳定 cost 的 `low` 判断、稳定 delta 告警以及 4.7 的零利用率残留阈值；不重置数据基线，不生成虚构采样，不撤回历史邮件。
- 每条规则结果和历史邮件保存当时生效的预设标识/版本及 `high/medium/low` 快照，之后修改预设不能改变历史解释。
- 正被全局引用的预设不得删除，必须先切换全局预设。仅被账户引用的预设可删除；删除前弹窗展示受影响账户数量并要求确认，删除后这些账户改为继承全局预设。
- 账户列表支持按条件筛选（至少能筛选正在使用指定预设的账户），对筛选结果批量修改。用户单选一个配置项时只改该项；多选时每项依自身规则修改，未选项保持不变。系统识别真实操作依赖并按顺序执行；预设选择变化与邮件开关变化是独立设置，不因可能改变后续邮件结果而视为依赖。整批修改原子提交；依赖步骤失败时全部回滚并显示原因。操作前显示目标账户和拟修改项，操作结果进入审计。

### 4.6 异常采样、两次跳变与恢复

每个监控账号分别维护 cost 异常事件和 delta 异常事件；两个事件可以同时存在，使用独立去重键、恢复条件和邮件记录：

1. 首个稳定 cost 低于生效 `low`，或后续稳定 cost 相对前值下降超过配置比例时建立 cost 事件，发送一封标明触发原因的 cost 异常邮件，并把该账号切换到默认 30 秒告警采样间隔。同一未恢复 cost 事件不重复发信或再次切换间隔。
2. 沿用 1.0 版的加速观察计数：触发 cost 事件的跳变样本不计入后续观察；其后的第一次 utilization 增加保存为观察起点，第二次增加完成加速观察区间。平台期样本不增加计数；一次跨越多个百分点仍算一次被观察到的变化，记录低精度标记，不补造中间边界。
3. 稳定 delta 首次低于生效 `low` 时建立独立 delta 事件并产生 delta 提醒；若自动暂停策略允许，同时调用暂停 API。该提醒不替代 cost 提醒；同一跳变若也命中稳定 cost 规则，两项提醒合入一封邮件，分别记录两个事件。
4. 自动暂停成功、加速观察窗口完成或 cost 事件提前恢复时，立即恢复普通采样间隔。只要 cost 事件尚未恢复，就保留事件锁，不再反复加速。
5. cost 事件只由后续稳定 cost 指标严格上升恢复；delta 事件只由后续稳定 delta 严格大于 medium 恢复。两者不要求在同一跳变同时恢复，也不能互相代替。
6. 暂停失败或结果未知不能标记成功。额度指标恢复不会自动调用 `schedulable=true`；如需恢复 Pixel 调度，由管理员确认后操作。

建议持久化实时基准、首次跳变锚点、进程启动代次、事件类型/ID、观察计数、边界样本、当前间隔、恢复锁和动作状态，使重启不会重复发送旧事件邮件。基线重置会结束上一计算周期的稳定比较与加速观察状态；历史事件和邮件仍可审计。长期没有 utilization 增加时不虚构稳定指标；目前没有已确认的超时退出值，保持当前间隔并显示“等待跳变”。

### 4.7 数据回退与零利用率邮件

除稳定 cost/delta 规则之外，原始字段回退单独判定；某条记录成为新基线时，不产生该条记录的稳定指标提醒或自动暂停。每次**新的回退或 cost 下降**都是新事件。同一采样可记录多个命中原因，但邮件统一走 4.8 的开关过滤与合并机制；同一原始采集的 ETL 重试不得重复发送。

| 当前采样条件 | 独立邮件 | 计算状态 |
|---|---|---|
| utilization 较前一成功采样回退到非零值，cost 不下降 | utilization 异常回退提醒：列出旧/新百分比，不按正常重置处理 | 当前记录成为新基线 |
| utilization 较前一成功采样回退到非零值，cost 同时下降 | utilization 与 cost 各产生异常回退提醒；开关过滤后按 4.8 合并，两项都启用时邮件列出各自旧/新值并提示高度注意 | 只执行一次基线重置；不能发送两封原始回退邮件 |
| utilization 从非零回退到 0，cost 下降或不下降 | **一封可能重置提醒**，列出 utilization 旧/新值和 cost 旧/新值；这条记录的 cost 伴随归零不单独发回退邮件 | 当前记录成为新基线 |
| utilization 未回退、当前值非零，cost 下降 | 独立 cost 下降邮件，列旧/新 cost 并提示高度注意 | 当前记录成为新基线 |
| utilization 持续为 0，cost 下降 | 无新的 utilization 回退邮件；**发独立 cost 下降异常邮件**，列旧/新 cost 并提示异常。零利用率 cost 高值事件按当前 cost 是否仍超阈决定持续或恢复 | 当前记录更新基线；本条实时 delta 为“基线更新，不可计算” |

当 utilization 为 0，额外计算 `zero_cost_limit = 当前账户生效 high * 0.01 * 2`，默认 high=3000 时阈值为 60，**严格大于**阈值才进入零利用率高 cost 异常。首次采样越阈时，提醒注明“首次采样 cost 偏高，请检查 high 是否设置得过于保守及上游数据口径”；从非零回退到 0 且越阈时，提醒注明“可能重置，cost 残留过高，请检查数据或系统状态”。若 utilization 持续为 0 后才越阈，提醒注明“零利用率下 cost 超出当前警戒线”，并说明本次是 cost 变化还是预设阈值变化。上述提醒共用一套零利用率高 cost 邮件开关；与同条其他已启用提醒按 4.8 合并。首次/重置记录作为基线，其实时 delta 显示不可计算，不能显示 0。

utilization 回退、一般原始 cost 下降、零利用率 cost 过高三类提醒分别有独立全局开关，默认发送；每个账户分别有“继承/开启/关闭”三态。全局关闭时所有账户不发送，但保存账户原设置；全局重新开启后，继承或开启的账户恢复发送，关闭的账户仍不发送。三类提醒沿用账户/管理账号的收件人路由。每次新的 utilization 回退或一般原始 cost 下降都是新数据异常事件，连续采样各出现新的回退仍各算新事件。**只观察到 utilization 回退至非零值时，直接按异常回退处理；即使采样间隔加大，也不推测曾错过 0 或改判为正常重置。**一般 cost 下降的唯一豁免是**当前记录刚从非零 utilization 回退到 0**，该条由可能重置提醒统一告知。零利用率 cost 超阈值则是持续状态：首次满足时提醒，后续持续超阈不重复提醒；出现 `cost <= 当前生效阈值` 或 `utilization > 0` 的采样即恢复，日后再次满足时重新提醒。稳定额度指标异常也按自身恢复条件去重。所有提醒是否进入邮件及同条合并方式见 4.8。

### 4.8 同条提醒过滤与邮件合并

对同一监控账户的**同一条采样**，先完成原始数据异常与稳定指标规则判定。原始字段回退或 cost 下降导致该条成为新基线时，该条不进入稳定指标告警；零利用率高 cost 规则仍可同时命中。然后按各提醒类型的全局/账户邮件开关过滤：关闭的提醒**对邮件组装视为未触发**，不参与合并，原始数据和规则审计仍保留。

- 过滤后无提醒：不发邮件；仅一项：使用该项的普通邮件主题和正文；两项或更多：**只发一封**，主题和正文明确写“多合一提醒”，逐项列出触发原因、前后值、有效阈值、精度提示和处理建议。
- 例如同条 utilization 与 cost 都回退至非零值，两个提醒都开启时是一封多合一邮件；一开一关时仅发送开启项的普通邮件；两项都关闭时不发。`U:16→0、C:350→80` 且生效 high=3000 时，若“可能重置”和“零利用率 cost 超过 60”两项都开启，也只发一封多合一邮件。
- 稳定 cost 和稳定 delta 可保持**两个独立业务事件**及各自恢复锁，但同一跳变若两者都产生邮件提醒，也只发一封多合一邮件。每个事件关联同一次邮件投递；同一采集 ETL 重试或邮件重试不得重复生成第二封已成功的通知。

### 5.2 密钥和机密信息

| 编号 | 需求 | 验收要点 |
|---|---|---|
| SEC-01 | 首次启动生成两个 16 字节随机值并编码为 32 个十六进制字符，分别作为数据库加密密钥和机密信息加密密钥；写入应用根目录 `.env` 并加载为环境变量。 | 只在首次初始化生成；重启不重复覆盖；开发仓库中的 `.env` 已被 Git 忽略，值不写入日志、示例配置或提交内容；应用按目标系统能力创建为仅运行账号和部署管理员可访问，并在权限不符合要求时阻止启动或给出明确错误。 |

| SEC-04 | 推荐 SQLCipher 4 默认格式；两个密钥独立轮换，任一轮换期间暂停对外数据库服务。机密信息轮换使用旧密钥解密、用新密钥重加密全部受保护记录。 | 提示“更换密钥会暂停数据库服务，轮换加密需要时间”；进度可查、失败可恢复。内部迁移访问不属于对外数据库服务。 |
| SEC-05 | 数据库密钥轮换时继续抓取上游原始 JSON，但暂停 ETL 入库；轮换成功后按时间顺序补偿入库。 | 原始文件不丢失；轮换结束后补偿任务可重试且不重复生成采样。 |

| SEC-07 | Windows 和 Linux 的 `.env` 与加密数据库仅通过操作系统或服务器文件管理方式取得、备份和恢复；Web 不提供下载、导出、备份或恢复入口。 | 使用相互匹配的 `.env` 和一致性加密数据库可恢复；缺少任一文件、密钥版本不匹配或数据库副本不一致时拒绝启动正常服务并给出可诊断错误，不承诺恢复。 |

数据库口令、Web 登录密码和机密信息密钥是三个不同概念。建议将数据库密钥生成的 32 个 hex 字符按原样作为文本口令交给 SQLCipher，通过其密钥派生机制处理；DBX 输入相同文本。不得把这 32 个字符当作 SQLCipher 的 32 字节原始密钥（原始密钥模式要求 64 个 hex 字符）。相关依据见架构第 6.1/9 节。

打开数据库只解开文件层：usage 等普通字段可读，第二密钥保护的 Token/密码等字段仍为密文。独立机密信息密钥轮换不能改变数据库口令。

本地登录密码继续要求不可逆校验。建议将带随机盐的密码哈希再用机密信息密钥加密，使哈希本身可重新加密；不保存可还原的本地明文密码，也不直接把可轮换密钥当作密码盐。`.env` 与数据库的文件权限、系统级备份和跨机器恢复责任由部署管理员承担，产品只负责安全创建、读取、轮换和校验，不提供 Web 文件备份能力。

## 6. 核心流程

### 6.1 首次启动与登录

1. Windows 首版由单个 `.exe` 启动，Linux x86_64 版由单个可执行文件启动；首次运行均在程序文件同目录原子创建 `.env` 和加密数据库，加载密钥后建库，重启不得覆盖已有文件。文件定位不依赖启动命令的当前工作目录。当前建议为 SQLCipher 4 默认格式。两端其他设置均经 Web 保存到数据库。
2. 创建默认本地管理员。
3. 管理员使用默认凭据登录。
4. 系统强制进入修改密码页；修改成功后才进入仪表盘。
5. 管理员配置 Pixel 租户、管理账号凭据、SMTP、分账号通知人和采集策略。

### 6.2 一次采样

1. 调度器选择到期且启用监控的 OpenAI 账号；Pixel 调度暂停不等于本地监控暂停。
2. 使用有效 Pixel Token 请求 usage。
3. 将完整响应写入原始 JSON 文件并记录文件状态。
4. 解析 seven_day 字段，取得上一成功采样、本周期实时基准、上一次 utilization 增加记录、基线阶段及账户当前生效预设。
5. 先判断 utilization 回退、原始 cost 下降及零利用率 cost 是否过高；需要重置时将当前记录作为新基线，邮件按 4.7 的精确条件分别建立。utilization 持续为 0 而 cost 下降时既发一般 cost 下降异常邮件，也更新基线，避免误导性的负实时 delta。其余记录计算实时指标；utilization 增加时先按旧基准计算当前实时 delta，再按预热阶段计算稳定指标，最后更新下一条的实时基准与跳变起点。
6. 仅用稳定指标判断首值是否低于 low、后续 cost 下降比例和 delta 档位；跨越多个百分点时按实际差值计算 delta，附精度提示并继续判断。事务内写入采样、基线/锚点、预设与阈值快照、规则结果和同步日志。
7. 按独立事件类型和邮件开关发送邮件；仅按稳定 delta 与自动暂停策略调用 Pixel PUT API。
8. 更新账号下一次采样时间，并执行可异步运行的原始文件清理。

### 6.3 密钥轮换

1. 管理员通过密码验证并确认影响范围。
2. 准备运行所需的采集配置与凭据快照，进入维护状态、排空数据库操作，暂停对外数据库读写及 ETL。
3. 上游抓取继续运行，原始 JSON 继续落盘。
4. 完成数据库密钥切换或全部机密字段重加密，并准备新的 `.env` 内容。
5. 验证使用新密钥可读写、存量数据可解密、事务一致，再原子替换 `.env` 并完成密钥版本切换。
6. 恢复 ETL，按原始文件时间顺序补偿入库。
7. 轮换失败时恢复旧状态并显示可操作的重试信息。

## 8. 外部接口

### Pixel 接口

以关联项目接口文档为准：

- 登录页和 POST /api/v1/auth/login。
- GET /api/v1/accounts 获取账号列表。
- GET /api/v1/accounts/{account_id}/usage?source=local&timezone=Asia%2FShanghai 获取用量。
- PUT /api/v1/accounts/{account_id}，请求体 {schedulable:false/true} 控制调度。

接口 host、port、超时和时区不得硬编码在业务逻辑中。网络失败、401、业务错误和格式错误必须区分记录。产品只通过 Web 提供管理入口，不为数据库实现 SSH 或其他远程访问接口，也不提供 `.env` 或数据库文件的 Web 下载、导出、备份和恢复接口。

### 邮件接口

首版采用 SMTP。收件人由 Web 页面配置；服务器、端口、TLS、发件人和凭据建议在同一页面输入，凭据按机密信息保护。测试邮件必须使用同一套连接配置，凭据录入方式见 11.2。

## 9. 非功能要求

- 安全：密码使用强哈希；会话 Cookie 设置 HttpOnly、Secure（启用 HTTPS 时）和 SameSite；可逆业务凭据加密；页面和日志不显示 Token、密码或完整密钥。根密钥仅允许存在于受限权限的 `.env`、受控进程环境和管理员重新验证后的专用短时查看入口。
- 一致性：原始文件状态与数据库采样状态可追溯；同一采样重试不产生重复有效记录。
- 隔离性：单账号网络或解析失败不能阻断其他账号；数据库写入使用事务。
- 可恢复性：任务失败可重试；服务重启后恢复未完成任务；密钥轮换具备失败恢复状态。整机或跨机器恢复依赖部署管理员通过操作系统保存的、相互匹配的 `.env` 与一致性加密数据库文件，缺少任一项不承诺恢复。
- 性能：在配置采样间隔内完成一轮账号采样；并发度可配置且不压垮 Pixel API。
- 可观测性：所有后台任务都有状态、耗时、错误和最近成功时间。
- 部署：Windows 首版提供单 `.exe`；后续 Linux x86_64 以单可执行文件运行，由 Nginx 提供外部访问和 TLS。Linux 的开机启动与进程异常退出后的拉起由操作系统服务管理承担，应用不实现自启动或自重启机制。

## 10. 验收标准

1. Windows 与 Linux 首次登录均不能绕过强制改密；修改后才能进入仪表盘。
2. 修改后的账号密码可正常登录；默认密码登录会产生安全提示。
3. 给定平台期、+1 和跨多个百分点的样例，四指标符合第 4.2 节公式；跨百分点的稳定 delta 使用实际差值，稳定 cost 使用跳变当次 `cost/(utilization-1)*100`，指标仍可告警但须提示精度。
4. 初始化、重启、utilization 回退及原始 cost 下降统一重置基线：重启首条不与旧样本比较补发回退邮件；基线记录实时 delta 为不可计算，第一次后续增加只建起点，第二次增加才生成稳定 cost/delta；跳变当条实时 delta 使用更新前的基准，不被归零。utilization 持续为 0 而 cost 下降时产生独立异常提醒并更新基线；仅刚从非零回退到 0 的归零下降豁免一般 cost 下降提醒。
5. 第一个稳定 cost 低于生效 low 时发送 cost 邮件并加速；从第二个稳定 cost 起仅比较相对前值，严格下降超过默认 5% 才触发，恰好 5% 不触发；仅凭 cost 异常不自动暂停。
6. 稳定 delta 低于最低阈值时产生独立 delta 事件，全局和账号策略组合结果正确；关闭自动暂停时不调用暂停 API，同一跳变同时命中 cost 与 delta 时只发一封多合一邮件，两个事件的状态分别记录。
7. 暂停 API 返回失败时，账号不会显示为已暂停，系统会重试并记录错误。
8. 密钥轮换期间原始 JSON 持续产生、ETL 暂停；轮换完成后数据可补偿入库。
9. 原始文件清理只删除已成功入库且满足保留时间或缓存上限的文件。
10. Windows 单个 `.exe` 首次点击运行后在同目录生成 `.env` 与加密数据库；重启不覆盖文件，Web 保存的配置、采样、事件阶段、日志和密钥状态仍可恢复。
11. 多租户及多个管理账号独立认证；非 OpenAI 账号不采样；同号 account_id 不跨租户串数据或串暂停目标。
12. cost 事件触发后，下一次被采到的 utilization 增加建立观察起点，再下一次增加完成观察区间；跨百分点变化不补造中间边界，计算锚点和告警观察计数分别持久化。
13. 自动暂停成功后继续普通采样；失败不伪造成功，额度恢复不自动开启 Pixel 调度。
14. 管理账号及监控账号的收件人路由正确，通知不会发送给其他账号的专属收件人。
15. 两个密钥均为 16 随机字节/32 hex 字符、可独立轮换；数据库和应用层机密都有恢复验证。
16. 应用创建的一致性加密库文件在取得到本地后，可在 DBX 输入数据库口令读表和业务记录，并用带 SQLCipher 支持的 DB Browser 交叉验证；不测试或承诺 SSH 远程直连。
17. 两个密钥首次初始化写入应用根目录 `.env`，后续轮换原子更新；文件与实际数据使用同一版本。数据库新口令可在本地客户端打开新文件，旧口令不能打开轮换后的文件，机密字段仍为密文。
18. 四种 utilization 回退/cost 下降交叉场景以及后续 `0→0、cost 下降` 严格按 4.7 矩阵判定；同条多提醒按 4.8 过滤与合并。刚回退到 0 且 cost 也下降时只产生可能重置提醒；若同时 cost 超过零利用率警戒线，将已启用的高残留提醒合入同一封。默认警戒线为 60。重启首条不与重启前数据比较补发；只回退到非零值一律判异常。
19. 三类数据异常邮件各有独立全局开关和账户级继承/开启/关闭；全局关闭时保留账户配置。连续新回退/一般 cost 下降各算新事件，同一采样两项原始回退只产生一封；零利用率高 cost 在持续超阈期间仅发一封，恢复后再越阈才重发；同一采集 ETL 重试不重复发送。
20. 多套命名预设可在全局和账户层级选用；编辑引用中预设或切换选择从下一条成功采样起生效，历史阈值快照不变；全局引用预设禁止删除，账户引用预设删除需确认并回退继承全局。
21. 账户筛选包含所用预设，批量修改只改所选配置项；多项修改依赖有序，任一步骤失败整批回滚且记录原因。
22. Windows 与 Linux 的 Web 页面和接口均不能下载、导出、备份或恢复 `.env` 和数据库文件；部署管理员可通过操作系统取得相互匹配的 `.env` 与一致性加密数据库并完成恢复，缺少任一项时系统拒绝进入正常服务且不宣称数据可恢复。

- 收件人：账号显式列表覆盖管理账号默认列表，不自动合并；未配置时继承，最终为空时显示“通知未配置”。SMTP 和 Pixel 凭据建议在本地 Web 输入；README 未逐项回答凭据录入方式。
- 账号交叉可见：建议同租户相同 account_id 合并监控、显式选择负责采集/暂停的管理账号；先用样例核实租户内 ID 的共享语义。
- 跨百分点采样：按实际百分点差值计算稳定 delta，继续执行告警和暂停，同时在页面/邮件/审计附低精度提示；稳定 cost 按当前 cost/(当前 utilization−1)×100，不沿用旧 O/N 平均公式。
- 缓存全部未抽取：禁止删除待处理数据；无法容纳新文件时暂停新抓取、展示积压/空间告警，腾出空间后恢复。“轮换期间采集继续”以可用缓存和上游认证有效为前提。
- 默认密码异常登录：建议继续限制到改密页；最小密码长度、会话过期、重试参数在实现设计中明确，不视为已有配置。
- 全局自动暂停关闭只抑制自动暂停动作，保留账户暂停偏好；账户所选阈值预设仍生效并决定邮件与档位。三类数据异常邮件的全局关闭也只抑制该类发送，保留账户三态配置。
- 脱敏契约样例：补齐 usage、分页账号列表、PUT 成功/失败、认证失败；关联项目的封装行为不是本项目已实现能力。
- 实施验证：建立工程前记录后端语言/框架、SQLCipher 绑定和版本；验证 SQLCipher 4 默认参数、口令语义、事务/轮换、DBX 与 SQLCipher 版 DB Browser 的本地打开能力。Linux 已确定为 x86_64，发行版/版本、运行账号和部署目录在最终封包前提供并完成兼容性验证，不阻塞此前开发；`.env`/数据库的系统级取得、备份和恢复边界已按 R2 定稿。依据见架构第 6.1、8、9 节。
