## 1. 产品概述

系统为添加在 Pixel 上的 OpenAI 账号建立本地监控。它按配置周期读取账号的 seven_day 用量，将原始响应落盘并将结构化数据写入 SQLite，计算额度估算值。当估算额度异常下降或单位增量消耗低于阈值时，系统发送邮件告警，并可按策略暂停异常账号的调度。

系统输出的是基于 usage 数据的估算结果，不替代 Pixel 的账单或官方额度结算。

## 2. 产品目标

### 必须达到

- 管理员能够安全登录、修改默认凭据和管理监控配置。
- 系统能够周期性获取所有启用监控账号的 seven_day 数据，并保留可追溯的原始响应。
- 每条采样都能得到两个实时指标或明确的不可计算原因；有效 utilization 跳变能得到相应稳定指标或明确的预热/重建基线原因。
- 同一本地管理员可接入多个 Pixel 租户及每租户的多个管理账号。
- 额度异常能够通过邮件通知；账号级策略启用时能够调用 Pixel API 暂停调度。
- Token、Pixel 凭据和 SMTP 凭据不得明文写入数据库或日志。两个根密钥按明确要求保存在本机应用根目录 `.env`，不得提交、打印或通过普通页面暴露。
- 支持在经过验收的 DBX 本地连接中凭数据库密码直接读取表结构与普通业务数据；应用层加密的机密字段仍保持密文。
- Windows 测试包可运行；架构为后续 Linux + Nginx 部署保留空间。

### 不在本期范围

- Pixel 账单结算、充值或额度购买。
- 修改 Pixel 的账号密码、API Key 或模型配置。
- 本地应用的多组织权限隔离、多人协作、细粒度角色权限和移动端 App；连接多个上游 Pixel 租户属于本期范围。
- 替代 Pixel 管理后台的全部账号管理能力。
- SSH 隧道、远程数据库协议、通过 DBX 直接打开服务器上的活动数据库，以及由产品代替用户登录服务器下载数据库文件。

## 3. 角色与权限

首版只有一个本地管理员角色。管理员可以查看和修改所有系统配置、账号策略、密钥和审计记录。未登录用户只能访问登录页。密钥查看和轮换还需要分别进行操作级密码验证。

术语分为三级：Pixel 租户是配置的上游连接范围；Pixel 管理账号是用于登录和获取 Token 的身份；监控账号是账号列表中的 OpenAI account_id。不同租户的同号 account_id 不能混用，管理账号登录名也不能脱离租户单独作为全局标识。

## 4. 核心术语和计算口径

### 4.1 原始字段

从 seven_day 保存 utilization、requests、tokens、cost、user_cost；同时保存租户、管理账号、监控账号引用，请求时间、上游 updated_at（若有）、source、timezone、原始文件路径和处理状态。

关联 API 文档只给出部分结构体：cost/user_cost 对应 SevenDay.WindowStats；requests/tokens 的具体 JSON 路径、空值行为需用脱敏响应补齐，不能猜测字段后声明已确认。该关联文档中的 `estimated_total_quota = round(cost / utilization)` 是关联项目的旧业务算法，只能作为字段/API 参考，不能覆盖本 PRD 的四指标公式。

### 4.2 额度指标

同一监控账号按成功采集顺序处理样本。设当前样本为 N，紧邻前一成功样本为 O，最近一次被接受的 utilization 跳变样本为 J。utilization 保存 0–100 的原始百分数，公式统一乘以 100。为避免把采样停留在同一百分点期间的 cost 累积误判为稳定额度下降，本期区分“稳定指标”和“实时指标”。

只有 `utilization(N) = utilization(O) + 1` 才建议认定为一个可计算的有效跳变。相同 utilization 是平台期；下降、重置、增加超过 1、缺失或非数字均不补造中间点，保存原因并重建跳变基线。该异常跳变处理是当前建议边界，待 R1 最终确认。

1. `credit_limit_by_cost`：仅在有效跳变 N 计算，公式为 `((cost(O) * 0.5) + (cost(N) * 0.5)) / utilization(O) * 100`。`utilization(O) <= 0`、cost 无效或跳变无效时记为不可计算。
2. `credit_limit_by_delta`：仅在有效跳变 N 且存在上一个有效跳变锚点 J 时计算，公式为 `(cost(N) - cost(J)) * 100`。初始化或进程重启后的第一个有效跳变只保存为新锚点，不输出该指标；cost 回退或锚点无效时重建基线。
3. `credit_limit_by_cost_real_time`：每条有效采样计算，公式为 `cost(N) / utilization(N) * 100`。分母为 0 时不可计算。
4. `credit_limit_by_delta_real_time`：存在当前跳变锚点 J 时每条采样计算，公式为 `(cost(N) - cost(J)) * 100`。没有锚点、cost 回退或锚点已失效时不可计算。若 N 本身是刚接受的有效跳变，先用旧锚点计算稳定 delta，再把 N 更新为新锚点，因此该条记录的实时 delta 按新锚点展示为 0。

稳定指标只写在实际完成计算的跳变采样上；平台期样本不得复制前一个稳定值冒充本次新计算。页面可另外展示“最近一次有效稳定值及其时间”。实时指标每条保存，但本期只用于提前观察，不参与邮件、采样加速、恢复或自动暂停。

所有指标保存原始精度，比较阈值前不按展示精度舍入；页面默认保留两位小数。数据库可继续用 -999 作为不可计算兼容值，但必须同时保存结构化原因；字段缺失、解析失败和预热状态不能伪装成正常零值。

### 4.3 utilization 单位和数值样例

上游值 57 表示 57%；从 57 到 58 是增加 1 个百分点。保存原始百分数，跳变识别和告警计数也使用该口径。

README 已给出量级样例：`cost=318.24, utilization=16` 时，`credit_limit_by_cost_real_time = 318.24 / 16 * 100 = 1989`。因此 3000/2400/1600 三档与乘以 100 后的总额度估算处于同一量级，不再保留“3000 还是 300000”的旧问题。

有效跳变示例：O 为 `cost=318.00, utilization=16`，N 为 `cost=318.48, utilization=17`，则稳定 cost 指标为 `((318.00 + 318.48) / 2) / 16 * 100 = 1989`。若上一跳变锚点 J 的 cost 为 298.59，则稳定 delta 为 `(318.48 - 298.59) * 100 = 1989`。

### 4.4 credit_limit_by_cost 趋势

只比较相邻两次有效计算得到的稳定 `credit_limit_by_cost`：

`variation_pct = (new_credit_limit_by_cost / last_valid_credit_limit_by_cost) - 1`。

- variation_pct < -告警阈值：下降超过阈值，触发异常。
- variation_pct >= 告警阈值：上升。
- 其余范围：基本持平。

默认阈值为 5%，可配置。严格遵循 README 的小于号，恰好下降 5% 不触发；当前或前值不可计算、前值为 0 或不存在时跳过并记录原因。cost 异常事件在后续有效稳定 cost 指标严格大于前一个有效稳定 cost 指标时恢复，不要求上涨达到 5%。实时 cost 指标不触发趋势告警。

### 4.5 credit_limit_by_delta 档位与暂停

默认 high=3000、medium=2400、low=1600，可配置，满足 high > medium > low。按 README，自动暂停默认开启；账号未设置覆盖值时使用全局默认策略。

| 指标范围 | 档位与动作 |
|---|---|
| 大于等于 high | 正常 |
| 大于等于 medium 且小于 high | 观察 |
| 大于等于 low 且小于 medium | 警告 |
| 小于 low | 严重异常，检查自动暂停策略 |
| 不可计算 | 跳过比较，不触发暂停；显示预热或质量原因 |

展示指标与三个阈值的差值。只有在有效跳变上得到的稳定 delta < low，且全局与账号策略均允许时，才自动暂停并建立 delta 异常事件；cost 下降和实时 delta 本身都不是自动暂停条件。初始化或重启后的第一跳只建立锚点，不能告警或暂停。

delta 异常事件在后续有效稳定 delta 严格大于 medium 时恢复；等于 medium 仍未恢复。恢复只解除本地事件锁，不自动把 Pixel 调度重新开启。

按 README，全局关闭时账号级配置不生效；当前文档按全局阈值继续比较和告警、只禁用自动暂停动作。若关闭仅应影响账号级暂停开关而不影响账号级阈值，需在评审中指出该区别，见 11.2。

### 4.6 异常采样、两次跳变与恢复

每个监控账号分别维护 cost 异常事件和 delta 异常事件；两个事件可以同时存在，使用独立去重键、恢复条件和邮件记录：

1. 稳定 cost 指标首次下降超过阈值时建立 cost 事件，发送一封 cost 异常邮件，并把该账号切换到默认 30 秒告警采样间隔。同一未恢复 cost 事件不重复发信或再次切换间隔。
2. 沿用 1.0 版的加速观察计数：触发 cost 事件的跳变样本不计入后续观察；其后的第一次有效 +1 跳变保存为观察起点，第二次有效 +1 跳变完成一个加速采样覆盖的完整百分点。平台期样本不增加计数，异常跳变会中止本轮区间并重建基线。
3. 稳定 delta 首次低于 low 时建立独立 delta 事件并发送一封 delta 异常邮件；若自动暂停策略允许，同时调用暂停 API。该邮件不替代 cost 邮件，同一跳变同时命中两条规则时允许分别发送两封。
4. 自动暂停成功、加速观察窗口完成或 cost 事件提前恢复时，立即恢复普通采样间隔。只要 cost 事件尚未恢复，就保留事件锁，不再反复加速。
5. cost 事件只由后续稳定 cost 指标严格上升恢复；delta 事件只由后续稳定 delta 严格大于 medium 恢复。两者不要求在同一跳变同时恢复，也不能互相代替。
6. 暂停失败或结果未知不能标记成功。额度指标恢复不会自动调用 `schedulable=true`；如需恢复 Pixel 调度，由管理员确认后操作。

建议持久化指标锚点、进程启动代次、事件类型、事件 ID、观察计数、边界样本、当前间隔、恢复锁和动作状态，使重启后先进入 delta 预热且不会重复发送旧事件邮件。长期没有有效跳变时不虚构稳定指标；当前没有已确认的超时退出值，因此保持当前间隔并显示“等待跳变”，不得擅自按定时器关闭事件。

## 5. 功能需求

### 5.1 本地登录和账号安全

| 编号 | 需求 | 验收要点 |
|---|---|---|
| AUTH-01 | Windows 与 Linux 首次初始化均提供默认账号 fuck_openai 和默认密码 pixel_test。 | 首次登录强制改密；重启不重置管理员凭据。 |
| AUTH-02 | 新密码不能等于默认密码，并满足配置的最小长度和复杂度。 | 使用默认密码提交修改时被拒绝，并给出明确原因。 |
| AUTH-03 | 初始化完成后每次登录都检查密码是否仍为默认值。 | 提示“非正常使用情况，你的密码与初始密码一致，存在安全隐患，请立即修改！”；建议继续限制到改密页，见 11.2。 |
| AUTH-04 | 只有已修改默认密码后，管理员才能修改登录账号。修改账号前必须重新验证当前密码。 | 默认密码状态下修改账号被拒绝；密码已修改且验证通过后才能保存。 |
| AUTH-05 | 会话具备过期、退出和失败登录限制。 | 过期后回到登录页；失败次数和锁定状态可在审计记录中查询。 |

### 5.2 密钥和机密信息

| 编号 | 需求 | 验收要点 |
|---|---|---|
| SEC-01 | 首次启动生成两个 16 字节随机值并编码为 32 个十六进制字符，分别作为数据库加密密钥和机密信息加密密钥；写入应用根目录 `.env` 并加载为环境变量。 | 只在首次初始化生成；重启不重复覆盖；开发仓库中的 `.env` 已被 Git 忽略，值不写入日志、示例配置或提交内容。 |
| SEC-02 | 管理员输入密码后可分别查看两个密钥。查看每个密钥都要单独验证。 | 验证失败不显示任何密钥；成功后仅在受控页面短时显示。 |
| SEC-03 | 管理员输入密码后可分别轮换两个密钥；轮换成功时原子更新 `.env` 中对应变量。 | 保存前显示影响范围和预计暂停服务提示；取消或轮换失败不会把 `.env` 留在新旧值不一致的状态。 |
| SEC-04 | 推荐 SQLCipher 4 默认格式；两个密钥独立轮换，任一轮换期间暂停对外数据库服务。机密信息轮换使用旧密钥解密、用新密钥重加密全部受保护记录。 | 提示“更换密钥会暂停数据库服务，轮换加密需要时间”；进度可查、失败可恢复。内部迁移访问不属于对外数据库服务。 |
| SEC-05 | 数据库密钥轮换时继续抓取上游原始 JSON，但暂停 ETL 入库；轮换成功后按时间顺序补偿入库。 | 原始文件不丢失；轮换结束后补偿任务可重试且不重复生成采样。 |
| SEC-06 | 用户取得数据库口令及一致性加密数据库文件后，可在本地用已验收的 DBX 连接打开，不需要先导出明文库。产品不提供 SSH 隧道或远程数据库直连。 | 正确口令可读普通业务数据，错误口令被拒绝；数据库轮换后新口令可用、旧口令对新文件失效；记录客户端版本和加密参数。 |

数据库口令、Web 登录密码和机密信息密钥是三个不同概念。建议将数据库密钥生成的 32 个 hex 字符按原样作为文本口令交给 SQLCipher，通过其密钥派生机制处理；DBX 输入相同文本。不得把这 32 个字符当作 SQLCipher 的 32 字节原始密钥（原始密钥模式要求 64 个 hex 字符）。相关依据见架构第 6.1/9 节。

打开数据库只解开文件层：usage 等普通字段可读，第二密钥保护的 Token/密码等字段仍为密文。独立机密信息密钥轮换不能改变数据库口令。

本地登录密码继续要求不可逆校验。建议将带随机盐的密码哈希再用机密信息密钥加密，使哈希本身可重新加密；不保存可还原的本地明文密码，也不直接把可轮换密钥当作密码盐。`.env` 的文件权限、备份与跨机器恢复责任见 R2。

### 5.3 Pixel 账号和数据采集

| 编号 | 需求 | 验收要点 |
|---|---|---|
| DATA-01 | 配置多个 Pixel 租户；每个租户支持多个管理账号，凭据加密保存并完成登录、Token 保存和失效重登。 | Token 不出现在页面和日志；401 能定位到租户和管理账号并提示重新认证。 |

| DATA-03 | 对每个启用监控账号按正常采样间隔请求 usage 接口：默认 60 秒，可配置。 | 每次独立采集产生一条采样并计算两个实时指标；稳定指标只在有效跳变时写入。同一原始文件重试 ETL 不重复入库，不因 updated_at 或 utilization 相同而合并不同请求。 |

### 5.5 异常、告警和调度控制

| 编号 | 需求 | 验收要点 |
|---|---|---|
| ALERT-01 | 有效跳变生成稳定 credit_limit_by_cost 后，与前一个有效稳定值比较；下降严格超过默认 5% 且不属于同一未恢复 cost 事件时建立事件并发送一封 cost 异常邮件。 | 平台期和实时 cost 不触发；邮件包含租户、管理账号、监控账号、时间、稳定指标变化及受权限控制的详情链接。 |
| ALERT-02 | cost 事件建立后将该账号采样间隔切换为默认 30 秒的告警间隔；自动暂停成功、cost 提前恢复或加速观察窗口完成后恢复默认 60 秒间隔。 | 下一次调度使用新间隔；调度器显示账号当前间隔、cost/delta 事件、观察窗口和恢复原因。 |
| ALERT-03 | 有效跳变生成稳定 credit_limit_by_delta 后比较三档阈值；预热、异常跳变或不可计算时跳过。 | 页面展示稳定档位、与阈值差值及实时指标；实时 delta 不触发规则。 |
| ALERT-04 | 全局配置控制是否允许自动暂停；全局开启时账号级配置可以设置阈值和是否自动暂停。 | 全局关闭时任何账号都不自动暂停且账号级设置不生效；全局开启时账号级关闭可阻止该账号自动暂停。 |
| ALERT-05 | 稳定 delta < low 时建立独立 delta 事件并发送一封 delta 异常邮件；策略允许时调用 PUT /api/v1/accounts/{account_id}，请求体为 schedulable=false。管理员确认后的恢复操作使用 true。 | cost 与 delta 邮件分别发送和去重；按接口契约确认成功才标记已暂停并恢复普通采样。额度恢复不自动调用 true。 |
| ALERT-06 | 记录告警、邮件发送和调度变更的完整审计。 | 审计包含触发采样、规则版本、请求结果、重试和最终状态。 |
| ALERT-07 | cost 与 delta 各自的同一未恢复事件不能因快速采样重复发送。 | 每个事件类型成功发送后停止重复投递；同一跳变同时命中时允许发送主题和内容不同的两封邮件。 |
| ALERT-08 | Web 支持管理账号默认收件人及其下属监控账号的独立收件人。 | 不同管理账号、同一管理账号下不同 account 均可发给不同的人；继承与覆盖建议见 11.2。 |

## 6. 核心流程

### 6.1 首次启动与登录

1. 首次启动生成两个随机密钥，原子写入应用根目录 `.env`，加载为环境变量，再按通过兼容验收的加密方案建库；当前建议为 SQLCipher 4 默认格式。
2. 创建默认本地管理员。
3. 管理员使用默认凭据登录。
4. 系统强制进入修改密码页；修改成功后才进入仪表盘。
5. 管理员配置 Pixel 租户、管理账号凭据、SMTP、分账号通知人和采集策略。

### 6.2 一次采样

1. 调度器选择到期且启用监控的 OpenAI 账号；Pixel 调度暂停不等于本地监控暂停。
2. 使用有效 Pixel Token 请求 usage。
3. 将完整响应写入原始 JSON 文件并记录文件状态。
4. 解析 seven_day 字段，获取上一条成功采样、最近有效跳变锚点及进程启动代次。
5. 每条采样计算两个实时指标；只有有效 +1 跳变才计算稳定 cost，预热完成后才计算稳定 delta，并更新锚点。
6. 只用稳定指标计算趋势、档位和独立的 cost/delta 事件；在一个数据库事务中写入采样、锚点、规则结果和同步日志。
7. 按事件类型分别发送邮件；按稳定 delta 和自动暂停策略调用 Pixel PUT API。
8. 更新账号下一次采样时间，并执行可异步运行的原始文件清理。

### 6.3 密钥轮换

1. 管理员通过密码验证并确认影响范围。
2. 准备运行所需的采集配置与凭据快照，进入维护状态、排空数据库操作，暂停对外数据库读写及 ETL。
3. 上游抓取继续运行，原始 JSON 继续落盘。
4. 完成数据库密钥切换或全部机密字段重加密，并准备新的 `.env` 内容。
5. 验证使用新密钥可读写、存量数据可解密、事务一致，再原子替换 `.env` 并完成密钥版本切换。
6. 恢复 ETL，按原始文件时间顺序补偿入库。
7. 轮换失败时恢复旧状态并显示可操作的重试信息。

## 7. 数据要求

以下为待实现的逻辑集合，不表示已有表或迁移：

- app_users：本地账号、密码校验材料（强哈希；是否再用机密信息密钥封装由安全设计定稿）、初始化状态、失败次数。
- app_settings：采样、阈值、SMTP、时区、保留策略、缓存字节上限、全局开关。

- pixel_admin_accounts：所属租户、加密登录账号/密码、认证状态、默认通知人。
- pixel_sessions：所属管理账号、加密 Token/Cookie、实际可获取的有效期信息。
- monitored_accounts：所属租户、account_id、可用管理账号关系、基础信息、阈值/自动暂停/收件人覆盖。
- usage_samples：采集唯一标识、所属监控账号、原始字段、四个指标、紧邻前值引用、跳变锚点引用、进程启动代次、趋势、档位、采集时间、质量状态。
- raw_files：采集标识、归属、路径、字节大小、校验值、是否抽取、保留状态；数据库离线时还需可独立恢复的文件元数据。
- alert_events：事件类型 cost/delta、触发样本、规则版本、前后值、阶段、观察计数、边界样本、当前间隔、恢复锁和结束原因。
- email_deliveries：事件/通知类型、收件人快照、模板版本、结果、重试和时间。
- schedule_actions：所属账号、暂停/恢复请求、结果、最终状态、重试。
- job_runs：采集、ETL、清理、轮换任务的开始、结束、状态和错误。
- audit_logs：登录、配置、密钥操作（不含密钥值）、告警和调度操作。

时间统一以 UTC 存储，页面按配置时区展示。跨租户标识、同租户多管理账号交叉可见及幂等边界见架构文档。

## 8. 外部接口

### Pixel 接口

以关联项目接口文档为准：

- 登录页和 POST /api/v1/auth/login。
- GET /api/v1/accounts 获取账号列表。
- GET /api/v1/accounts/{account_id}/usage?source=local&timezone=Asia%2FShanghai 获取用量。
- PUT /api/v1/accounts/{account_id}，请求体 {schedulable:false/true} 控制调度。

接口 host、port、超时和时区不得硬编码在业务逻辑中。网络失败、401、业务错误和格式错误必须区分记录。产品只通过 Web 提供管理入口，不为数据库实现 SSH 或其他远程访问接口。

### 邮件接口

首版采用 SMTP。收件人由 Web 页面配置；服务器、端口、TLS、发件人和凭据建议在同一页面输入，凭据按机密信息保护。测试邮件必须使用同一套连接配置，凭据录入方式见 11.2。

## 9. 非功能要求

- 安全：密码使用强哈希；会话 Cookie 设置 HttpOnly、Secure（启用 HTTPS 时）和 SameSite；可逆业务凭据加密；页面和日志不显示 Token、密码或完整密钥。根密钥仅允许存在于受限权限的 `.env`、受控进程环境和管理员重新验证后的专用短时查看入口。
- 一致性：原始文件状态与数据库采样状态可追溯；同一采样重试不产生重复有效记录。
- 隔离性：单账号网络或解析失败不能阻断其他账号；数据库写入使用事务。
- 可恢复性：任务失败可重试；服务重启后恢复未完成任务；密钥轮换具备失败恢复状态。
- 性能：在配置采样间隔内完成一轮账号采样；并发度可配置且不压垮 Pixel API。
- 可观测性：所有后台任务都有状态、耗时、错误和最近成功时间。
- 部署：Windows 首版提供可运行包；后续 Linux 以单服务运行，由 Nginx 提供外部访问和 TLS。

## 10. 验收标准

1. Windows 与 Linux 首次登录均不能绕过强制改密；修改后才能进入仪表盘。
2. 修改后的账号密码可正常登录；默认密码登录会产生安全提示。
3. 给定平台期、有效 +1 跳变和异常跳变样例，系统能正确得到四个指标；稳定字段只在适用跳变上产生，不可计算时同时保存原因。
4. 初始化或重启后的第一个有效跳变只建立 delta 锚点；下一有效 +1 跳变才生成稳定 delta。实时 delta 在跳变记录更新锚点后为 0。
5. 稳定 cost 指标下降严格超过阈值时发送 cost 邮件并加速；恰好下降 5% 不触发；实时 cost 不触发规则，同一未恢复 cost 事件不重复发信或加速。
6. 稳定 delta 低于最低阈值时发送独立 delta 邮件，全局和账号策略组合结果正确；关闭自动暂停时不调用暂停 API，同一跳变可同时产生 cost 与 delta 两封不同邮件。
7. 暂停 API 返回失败时，账号不会显示为已暂停，系统会重试并记录错误。
8. 密钥轮换期间原始 JSON 持续产生、ETL 暂停；轮换完成后数据可补偿入库。
9. 原始文件清理只删除已成功入库且满足保留时间或缓存上限的文件。
10. Windows 测试包重启后配置、采样、事件阶段、日志和密钥状态仍可恢复。
11. 多租户及多个管理账号独立认证；非 OpenAI 账号不采样；同号 account_id 不跨租户串数据或串暂停目标。
12. cost 事件触发后，下一次有效 +1 跳变建立观察起点，再下一次有效 +1 跳变完成观察区间；计算锚点和告警观察计数分别持久化，不能互相覆盖。
13. 自动暂停成功后继续普通采样；失败不伪造成功，额度恢复不自动开启 Pixel 调度。
14. 管理账号及监控账号的收件人路由正确，通知不会发送给其他账号的专属收件人。
15. 两个密钥均为 16 随机字节/32 hex 字符、可独立轮换；数据库和应用层机密都有恢复验证。
16. 应用创建的一致性加密库文件在取得到本地后，可在 DBX 输入数据库口令读表和业务记录，并用带 SQLCipher 支持的 DB Browser 交叉验证；不测试或承诺 SSH 远程直连。
17. 两个密钥首次初始化写入应用根目录 `.env`，后续轮换原子更新；文件与实际数据使用同一版本。数据库新口令可在本地客户端打开新文件，旧口令不能打开轮换后的文件，机密字段仍为密文。

## 11. 待确认事项

### 11.1 三组需要定稿的产品决定

旧版十项问题和 README 1.3-draft 的明确答案已纳入正文。以下只保留会影响实现或恢复能力的边界；建议均不等于批准。

| 编号 | 需要确认的内容 | 建议及影响 |
|---|---|---|
| R1 跳变与窗口异常 | 是否接受“只有恰好 +1 才是有效跳变”；增加超过 1、下降、seven_day 重置或 cost 回退时重建基线并跳过稳定指标、告警和自动动作？进程重启后第一有效跳变仍可算稳定 cost，但只建立 delta 锚点；跳变当条实时 delta 按新锚点归零，是否接受？ | 建议接受。这样不会把缺失的中间百分点补造成真实样本，也符合“最近一次跳变”字面定义；原始采样和可计算的实时指标仍保留并显示质量原因。若希望跨多百分点折算或跳变当条沿用旧锚点展示，需另定义公式和可信条件。 |
| R2 `.env` 与恢复责任 | “根目录”在打包后解释为应用可执行文件/配置所在的应用根目录。是否由产品提供 `.env` 导出/备份入口，还是完全由用户随数据库文件一起安全备份？Windows/Linux 应用根目录的权限要求是否可接受？ | 建议产品不在普通 Web 页面提供 `.env` 下载；文档要求用户把 `.env` 与加密数据库作为同一恢复集合，通过操作系统权限保护并离线备份。缺少任一根密钥时不承诺恢复对应数据。 |
| R3 实现与部署目标 | 后端语言/框架、Windows 包形态、Linux 发行版/CPU 架构、服务账号和 Nginx 部署目录尚未确定。 | 建议先以 Windows x64 自包含测试包验证 SQLCipher/DBX、任务恢复和密钥轮换，再冻结 Linux 目标。产品仅暴露 Web 服务；数据库文件由用户通过服务器管理方式取得到本地，不开发 SSH/远程数据库功能。 |

### 11.2 随需求评审接受或调整的实现建议

- 收件人：账号显式列表覆盖管理账号默认列表，不自动合并；未配置时继承，最终为空时显示“通知未配置”。SMTP 和 Pixel 凭据建议在本地 Web 输入；README 未逐项回答凭据录入方式。
- 账号交叉可见：建议同租户相同 account_id 合并监控、显式选择负责采集/暂停的管理账号；先用样例核实租户内 ID 的共享语义。
- 跳变异常：一次跨多个百分点、回退或采集中断不能声称已观察到完整相邻边界；建议重新等待可识别区间并记录原因，见 R1。
- 缓存全部未抽取：禁止删除待处理数据；无法容纳新文件时暂停新抓取、展示积压/空间告警，腾出空间后恢复。“轮换期间采集继续”以可用缓存和上游认证有效为前提。
- 默认密码异常登录：建议继续限制到改密页；最小密码长度、会话过期、重试参数在实现设计中明确，不视为已有配置。
- 全局关闭的范围：当前按 README 字面解释为账号级设置整体不生效、使用全局阈值继续告警。若本意只禁用暂停动作、仍保留账号级阈值，应明确调整。
- 脱敏契约样例：补齐 usage、分页账号列表、PUT 成功/失败、认证失败；关联项目的封装行为不是本项目已实现能力。
- 实现前验证：SQLCipher 4 默认参数、口令语义、实际非 Go 绑定、事务/轮换及 Windows/Linux 打包；DBX 与 SQLCipher 版 DB Browser 的版本及本地打开能力。后端语言/框架、CPU 架构、`.env` 权限/备份、部署目录及缓存默认值尚未选定。依据见架构第 6.1、8、9 节。
