# 开发与交付计划

> 对应 PRD 1.3-draft，已吸收 README 和本轮逐项确认的指标、数据异常邮件、阈值预设与批量修改规则。当前没有后端/前端工程、依赖清单、迁移或 CI。Go 强制要求已取消，替代语言和框架尚未确定；以下是建议计划，不是已存在的命令或依赖。

## 1. 当前阶段和前置门

本轮只更新需求与设计文档，不创建业务代码、原型、迁移、安装包或依赖清单。计算、回退和同条邮件合并规则已逐项澄清；进入实现前还需确认 `docs/PRD.md` 的 R2–R3：

1. 应用根目录 `.env` 的操作系统权限、备份和跨机器恢复责任；是否明确不提供 Web 下载。
2. 后端语言/框架，以及 Linux 的发行版/版本、运行账号和程序部署位置。Linux 已确定为 x86_64 单个可执行文件，开机启动及异常拉起由操作系统负责；Windows 单个可点击 `.exe`、两端 `.env`/数据库同程序目录已确认。

还需取得脱敏 usage、账号列表、认证失败和暂停 PUT 响应样例，补齐字段契约。

## 2. 批准后的开发顺序

1. 固化 PRD、架构、页面清单和上游 DTO 契约；先按批准流程完成低保真、高保真和 Demo 的页面审核，再推进正式后端与联调。
2. 选定后端及 SQLCipher 绑定，锁定版本与 v4 默认参数；经授权实现后先验证单个 Windows `.exe` 首次在同目录生成 `.env`/加密数据库、重启保留、DBX 本地凭口令打开及跨平台加密备份，再建立工程、配置、日志、存储适配和迁移。
3. 实现本地认证、首次改密、默认密码检查、会话过期和操作级密码验证。
4. 实现多 Pixel 租户、租户下管理账号、加密凭据、登录/重登和 OpenAI 账号同步。
5. 实现原始 JSON 原子落盘、文件元数据、usage 解析、四指标、实时基准、统一重置阶段、跳变起点、进程启动代次和幂等 ETL。
6. 实现命名 high/medium/low 预设、全局/账户生效选择、历史阈值快照、筛选及原子批量修改；再实现普通/告警调度、加速观察、稳定指标事件和三类数据异常邮件开关、按账号收件人发送及审计。
7. 实现调度 PUT 控制、失败重试、人工恢复入口和 Web 页面状态。
8. 实现数据库口令轮换、机密信息密钥轮换、`.env` 原子替换、ETL 暂停/补偿和失败恢复；加入 DBX 用新口令重开的验证。
9. 实现按保留天数和缓存字节数清理、缓存满时背压和任务恢复。
10. 生成 Windows 测试包，执行测试计划和手工验收。
11. 根据 Windows 结果整理 Linux x86_64 单可执行文件、程序同目录 `.env`/数据库、Nginx 反向代理和备份恢复包；验证 Web 资源及 SQLCipher/加密组件随单文件正常运行。

## 3. 代码和契约约定

- 不要求 Go 模块或 Go 格式化/检查工具。语言与框架确定后选择对应格式化、静态检查、测试和构建工具并记录实际命令；未运行不写成已通过。
- 上游 DTO、内部领域模型和数据库模型分离；不得把上游 JSON 字段直接暴露给页面。
- 使用百分数 utilization 口径并按已确认公式乘以 100；保存原始值、四指标、算法版本和质量原因，不擅自转换为 0–1 比例。
- 稳定指标与实时指标使用不同字段和触发条件；稳定 cost 用当前 `cost/(utilization-1)*100`，稳定 delta 和实时 delta 均按实际百分点差值计算，实时分母仅在 0 时修正为 1。跳变当条先用旧实时基准计算，再更新下一条基准。平台期不得复制旧稳定值冒充新计算。
- 每次进程启动生成新的启动代次，首条成功采样建立基线；utilization 回退或原始 cost 下降也重建基线。一般 cost 下降每次可发独立邮件；仅刚从非零 utilization 回退到 0 的归零下降豁免，后续 `0→0` 的再次下降仍须发。第一次后续增加只建立稳定计算起点，第二次增加才生成稳定指标；第一个稳定 cost 只比较生效 low，后续只比较下降比例。事件、计算基准和加速观察计数不得复用一个状态字段。
- 跨越多个百分点仍参与告警及自动暂停，必须携带低精度提示。所有同一账户同一采样的提醒先按开关过滤，关闭项对邮件视为未触发；剩一项发普通邮件，两项以上只发一封标明“多合一提醒”的邮件，关联各独立事件及前后值。基线记录不触发稳定指标提醒，但可能重置与零利用率高残留可以合并。重启后首条不与旧样本比较补发，非零 utilization 回退一律判异常。
- 批量修改每个所选字段只改自己，真实依赖顺序执行，整批原子提交；预设切换/编辑从下一条成功采样生效，历史阈值快照不可变。
- usage 每次独立采集保留采集 ID；同一原始文件 ETL 重试幂等，不因 updated_at 相同合并不同采集。
- 所有时间在数据库保存 UTC，边界层按配置时区转换。
- 错误必须包含阶段、租户、管理账号和监控账号上下文，但不得包含 Token、密码、密钥或完整原始响应。
- schema 通过版本化迁移管理；迁移、加密数据库连接或密钥校验失败不能启动半可用服务。
- 外部互操作以 SQLCipher 4 默认格式、文本口令为建议基线；SQLCipher 不要求 Go，但仍需实际绑定和原生库打包。任何替代引擎必须生成相同格式并通过客户端验证，不能只按加密算法名称推断兼容。
- 数据库口令不能与 Web 登录密码混用；32 字符 hex 文本按 passphrase 输入，不误用为 32 字节原始密钥。两个根密钥从应用根目录 `.env` 加载，真实值不得进入命令行、日志、示例或版本控制。机密字段独立加密仍保留，依据见架构第 6.1/9 节。

## 4. 配置和运行

当前没有可验证的启动命令。实现后必须提供并在交付文档验证：

- Windows 单个 `.exe` 的开发启动、打包、点击运行、首次同目录创建 `.env`/数据库、重启及数据保留验证命令。
- 所选数据库组件的初始化、连接、密钥注入、关闭和健康检查方式；只有确为独立进程时才提供单独启动说明。
- Linux 服务启动、停止、健康检查、Nginx 反代和回滚命令；验证 `.env`/数据库以程序文件所在目录定位、服务账号具备所需写权限，不提供数据库 SSH 隧道或远程直连命令。
- Pixel host/port、租户、管理账号、SMTP、缓存目录和日志目录说明。
- 两个密钥的首次生成、应用根目录 `.env` 权限、加载、查看、独立轮换、离线备份和恢复说明。
- 初始管理员默认凭据和首次强制改密流程。

所有示例只能使用占位符；不得把 Token、密码、SMTP 密码或密钥写进配置示例、日志或提交内容。

## 5. 交付物

- Windows 单个可直接点击的 `.exe` 测试包及校验值；首次运行同目录生成 `.env` 和加密数据库，其余配置从 Web 写入数据库。
- 不含真实凭据的配置示例、加密参数基线、实际绑定与运行说明。
- 外部读取说明：如何在停写或一致性备份后取得加密数据库文件、DBX 本地打开、数据库口令、普通字段/二次加密字段的区别及轮换后重新连接。明确不支持 SSH/远程数据库直连。
- 数据目录、原始文件、加密数据库、密钥版本和备份恢复说明。
- 使用说明：首次登录、配置多租户、SMTP、账号收件人、三类数据异常邮件开关、命名预设/继承/删除、筛选批量修改、暂停和密钥轮换。
- 测试报告、未解决限制、上游契约差异和回滚步骤。
- Linux x86_64 单可执行文件与 Nginx 部署说明；发行版/版本及系统运行库兼容性须列为已验证事实或未验证建议。

## 6. 变更控制

修改四指标公式/时点、基线重置条件、默认阈值/预设继承、批量原子性、加速观察状态、邮件事件与开关、页面核心流程、数据表、上游接口、`.env` 密钥语义、加密文件格式/客户端兼容边界或部署模式时，先更新 PRD/架构/测试文档并说明原因。需求审核通过前不修改实现；实现阶段的实质变更应建立变更记录并重新经过相应审核门。
