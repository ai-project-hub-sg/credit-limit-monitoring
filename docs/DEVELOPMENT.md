# 开发与交付计划

> 对应 PRD 1.3-draft。当前没有后端/前端工程、依赖清单、迁移或 CI。Go 强制要求已取消，替代语言和框架尚未确定；以下是建议计划，不是已存在的命令或依赖。

## 1. 当前阶段和前置门

本轮只更新需求与设计文档，不创建业务代码、原型、迁移、安装包或依赖清单。进入实现前必须先确认 `docs/PRD.md` 的 R1–R3：

1. 计算量纲、seven_day 回退/重置和阈值含义。
2. 两次 1 个百分点异常生命周期、确认邮件和恢复条件。
3. 密钥保管、无人值守解锁、跨机器恢复和第三方访问方式；当前建议以 SQLCipher 4 默认格式及 DBX 本地打开作为基线。

还需取得脱敏 usage、账号列表、认证失败和暂停 PUT 响应样例，补齐字段契约。

## 2. 批准后的开发顺序

1. 固化 PRD、架构、页面清单和上游 DTO 契约；先按批准流程完成低保真、高保真和 Demo 的页面审核，再推进正式后端与联调。
2. 选定非 Go 后端及 SQLCipher 绑定，锁定版本与 v4 默认参数；经授权实现后先验证建库、DBX 本地凭口令打开及跨平台加密备份，再建立工程、配置、日志、存储适配和迁移。
3. 实现本地认证、首次改密、默认密码检查、会话过期和操作级密码验证。
4. 实现多 Pixel 租户、租户下管理账号、加密凭据、登录/重登和 OpenAI 账号同步。
5. 实现原始 JSON 原子落盘、文件元数据、usage 解析、指标计算和幂等 ETL。
6. 实现普通/告警调度、delta 档位、两次百分点状态、事件去重、按账号收件人发送邮件和审计。
7. 实现调度 PUT 控制、失败重试、人工恢复入口和 Web 页面状态。
8. 实现数据库口令轮换、机密信息密钥轮换、ETL 暂停/补偿和失败恢复；加入 DBX 用新口令重开的验证。
9. 实现按保留天数和缓存字节数清理、缓存满时背压和任务恢复。
10. 生成 Windows 测试包，执行测试计划和手工验收。
11. 根据 Windows 结果整理 Linux 单服务、密钥注入、Nginx 反向代理和备份恢复包。

## 3. 代码和契约约定

- 不要求 Go 模块或 Go 格式化/检查工具。语言与框架确定后选择对应格式化、静态检查、测试和构建工具并记录实际命令；未运行不写成已通过。
- 上游 DTO、内部领域模型和数据库模型分离；不得把上游 JSON 字段直接暴露给页面。
- 使用百分数 utilization 口径时，保存原始值和质量原因；指标未定稿前不擅自除以 100。
- usage 每次独立采集保留采集 ID；同一原始文件 ETL 重试幂等，不因 updated_at 相同合并不同采集。
- 所有时间在数据库保存 UTC，边界层按配置时区转换。
- 错误必须包含阶段、租户、管理账号和监控账号上下文，但不得包含 Token、密码、密钥或完整原始响应。
- schema 通过版本化迁移管理；迁移、加密数据库连接或密钥校验失败不能启动半可用服务。
- 外部互操作以 SQLCipher 4 默认格式、文本口令为建议基线；SQLCipher 不要求 Go，但仍需实际绑定和原生库打包。任何替代引擎必须生成相同格式并通过客户端验证，不能只按加密算法名称推断兼容。
- 数据库口令不能与 Web 登录密码混用；32 字符 hex 文本按 passphrase 输入，不误用为 32 字节原始密钥。机密字段独立加密仍保留，依据见架构第 6.1/9 节。

## 4. 配置和运行

当前没有可验证的启动命令。实现后必须提供并在交付文档验证：

- Windows 开发启动、打包、运行和数据目录命令。
- 所选数据库组件的初始化、连接、密钥注入、关闭和健康检查方式；只有确为独立进程时才提供单独启动说明。
- Linux 服务启动、停止、健康检查、Nginx 反代和回滚命令。
- Pixel host/port、租户、管理账号、SMTP、缓存目录和日志目录说明。
- 两个密钥的首次生成、保管、查看、独立轮换、备份和恢复说明。
- 初始管理员默认凭据和首次强制改密流程。

所有示例只能使用占位符；不得把 Token、密码、SMTP 密码或密钥写进配置示例、日志或提交内容。

## 5. 交付物

- Windows 可执行测试包及校验值。
- 不含真实凭据的配置示例、加密参数基线、实际绑定与运行说明。
- 外部读取说明：DBX 本地文件、数据库口令、普通字段/二次加密字段的区别、轮换后重新连接、Linux 加密一致性备份本地读取。DBX SSH Worker v1 的已知限制另列。
- 数据目录、原始文件、加密数据库、密钥版本和备份恢复说明。
- 使用说明：首次登录、配置多租户、SMTP、账号收件人、阈值、暂停和密钥轮换。
- 测试报告、未解决限制、上游契约差异和回滚步骤。
- Linux 单服务与 Nginx 部署说明；具体目标版本和架构须列为已验证事实或未验证建议。

## 6. 变更控制

修改计算公式、默认阈值、两次跳变状态、页面核心流程、数据表、上游接口、密钥语义、加密文件格式/客户端兼容边界或部署模式时，先更新 PRD/架构/测试文档并说明原因。需求审核通过前不修改实现；实现阶段的实质变更应建立变更记录并重新经过相应审核门。
