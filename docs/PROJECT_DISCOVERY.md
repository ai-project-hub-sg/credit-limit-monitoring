# 项目发现记录

> 对应 PRD 1.3-draft；已取消 Go 强制要求，新增第三方客户端凭口令打开目标。推荐 SQLCipher 4 默认格式，官方证据集中在 ARCHITECTURE.md 第 9 节。

## 1. 结论摘要

这是一个面向单机运维人员的 Pixel OpenAI 账号额度监控系统。系统通过 Pixel 的登录和账号接口定期读取 seven_day 用量，保存原始 JSON 和结构化采样，计算两个额度估算指标，在异常时发送邮件，并按全局和账号级策略选择是否关闭账号调度。

当前仓库没有业务代码、依赖清单、构建命令或 Git 历史。本阶段只形成需求和设计文档，不能声称已有构建、运行或测试能力。

## 3. 用户与场景

主要用户是部署该工具的管理员或运维人员：

1. 首次登录并修改默认密码。
2. 配置多个 Pixel 租户、租户下管理账号、SMTP 和监控参数。
3. 查看账号用量、额度估算、趋势、delta 档位和原始记录。
4. 收到异常邮件；策略允许时自动暂停 Pixel 调度，否则按提示人工处理。
5. 管理原始数据保留、缓存字节上限、密钥查看和独立轮换。

首版仍只有一个本地管理员角色；“多个租户”是上游连接能力，不是本地多人多组织权限。

## 4. 技术与复杂度判断

### 前端：中等

包含登录/改密、Pixel 连接、仪表盘、账号列表/详情、配置、通知、数据管理、安全设置和日志。需要维护状态、异常确认、密钥轮换维护态、加载/空/错误/无权限状态，以及账号级通知人和事件进度展示。低保真页面审核前不制作原型。

### 后端：中等偏高

包含多租户 Token、定时调度、原始文件队列、数据库 ETL、指标和两次百分点跳变、邮件去重、调度 PUT、独立密钥轮换和缓存背压。单账号失败必须与其他账号隔离。

### 数据库：必须保留

需要按租户、管理账号、监控账号和时间查询采样，保存前值引用、事件状态、邮件和调度审计。SQLite 已确定；建议使用 SQLCipher 文件加密、事务和受控单写队列。具体绑定、Windows/Linux 包及 DBX 本地互操作要在实现阶段验证。

### 语言和运行时

本轮已撤销后端必须使用 Go 的限制，语言、框架与构建工具未选定。SQLCipher 提供 C/C++ 接口，使用它不要求 Go；推荐基线不重新引入 Go。实际绑定、原生库与打包需另行选择。[来源见架构 S1]

此前 `sqlite3-encrypted` 的来源仍未核实，无法断言其格式；如果实际是 SQLite3 Multiple Ciphers，则可配置 SQLCipher 兼容模式，但不能使用任意默认参数后保证 DBX 打开。[来源见架构 S3]

## 5. 关键风险

- 公式按百分数值还是按 0–1 比例解释会让指标和 3000/2400/1600 阈值相差 100 倍；需用数值样例确认量纲。
- 两次 1 个百分点跳变、完整区间“仍异常”、同一事件邮件数量和恢复同条样本条件尚未完全定稿。
- SQLCipher 默认格式与口令模式有官方依据，但实际驱动包、DBX 客户端版本、轮换后重开及跨平台备份互操作尚未实测。
- DBX SQLite SSH Worker v1 官方文档不支持远程 SQLCipher；本地文件支持不能自动推广为远程直连支持。[来源见架构 S5]
- 本地密码必须不可逆；如何用第二密钥保护密码校验材料、如何注入启动密钥仍影响恢复和轮换。
- usage 的 requests/tokens 字段、分页、Token 失效和暂停 PUT 成功响应需脱敏样例确认。
- 原始缓存满且全部文件未抽取时不能删除待处理数据，需要明确背压和恢复行为。

## 6. 仍需确认与下一道审核门

`docs/PRD.md` 第 11 节 R1–R3 是当前唯一需要用户定稿的三组问题：

- R1：公式量纲、seven_day 回退/重置和默认阈值。
- R2：异常生命周期、首次/确认邮件数量、完整区间判据和恢复时点。
- R3：密钥保管、无人值守解锁、跨机器恢复与是否需要直接远程访问；推荐基线和技术验证项已给出，不再要求用户必须找到未知包。

此外需补齐脱敏 usage、分页账号列表、认证失败和暂停 PUT 响应样例。确认后才能进入低保真页面和技术实现设计；在确认前不创建原型、后端、前端、迁移或安装包。
