# 项目发现记录

> 对应 PRD 1.3-draft；已吸收 README 及本轮逐项确认的指标、统一基线、数据异常邮件、阈值预设和原子批量修改。推荐 SQLCipher 4 默认格式，官方证据集中在 ARCHITECTURE.md 第 9 节。

## 1. 结论摘要

这是一个面向单机运维人员的 Pixel OpenAI 账号额度监控系统。系统通过 Pixel 的登录和账号接口定期读取 seven_day 用量，保存原始 JSON 和结构化采样，逐采样计算两个实时指标，并在统一基线后的第二次 utilization 增加起计算两个稳定指标。稳定 cost/delta 和数据回退异常分别发邮件，并按全局与账户策略选择是否关闭账号调度。用户可维护多套命名阈值预设，全局及账户各选择一套生效。

当前仓库使用 Git `main` 分支，已有需求文档提交历史；仓库仍没有业务代码、依赖清单、构建命令或 CI。本阶段只形成需求和设计文档，不能声称已有构建、运行或测试能力。

## 3. 用户与场景

主要用户是部署该工具的管理员或运维人员：

1. 首次登录并修改默认密码。
2. 配置多个 Pixel 租户、租户下管理账号、SMTP 和监控参数。
3. 查看账号用量、两项稳定指标、两项实时指标、当前阈值预设、趋势、delta 档位和原始记录。
4. 分别收到稳定 cost/delta 及数据异常邮件；策略允许时自动暂停 Pixel 调度，否则按提示人工处理。
5. 管理原始数据保留、缓存字节上限、密钥查看和独立轮换。

首版仍只有一个本地管理员角色；“多个租户”是上游连接能力，不是本地多人多组织权限。

## 4. 技术与复杂度判断

### 前端：中等

包含登录/改密、Pixel 连接、仪表盘、账号列表/详情、命名预设、按预设筛选与批量修改、通知配置、数据管理、安全设置和日志。需要维护状态、异常确认、密钥轮换维护态、加载/空/错误/无权限状态，以及账号级通知人和事件进度展示。低保真页面审核前不制作原型。

### 后端：中等偏高

包含多租户 Token、定时调度、原始文件队列、数据库 ETL、四指标与双基准、统一重置阶段、独立数据异常邮件开关、预设版本快照、原子批量修改、调度 PUT、`.env` 原子轮换和缓存背压。单账号失败必须与其他账号隔离。

### 数据库：必须保留

需要按租户、管理账号、监控账号和时间查询采样，保存实时基准、跳变锚点、基线阶段、启动代次、生效预设及阈值快照、各类独立事件、邮件和调度审计。SQLite 已确定；建议使用 SQLCipher 文件加密、事务和受控单写队列。具体绑定、Windows/Linux 包及 DBX 本地互操作要在实现阶段验证。

### 语言和运行时

本轮已撤销后端必须使用 Go 的限制，语言、框架与构建工具未选定。SQLCipher 提供 C/C++ 接口，使用它不要求 Go；推荐基线不重新引入 Go。实际绑定、原生库与打包需另行选择。[来源见架构 S1]

此前 `sqlite3-encrypted` 的来源仍未核实，无法断言其格式；如果实际是 SQLite3 Multiple Ciphers，则可配置 SQLCipher 兼容模式，但不能使用任意默认参数后保证 DBX 打开。[来源见架构 S3]

## 5. 关键风险

- README 中旧 O/N 平均公式已被用户本轮修正；开发时必须使用 PRD 的当前 cost/(utilization−1) 与按实际百分点差值计算的 delta，不可复制旧公式。
- 零利用率高 cost 持续超阈仅发一封，恢复后再越阈才重发；utilization 持续为 0 时 cost 再下降是新的原始 cost 异常，发送独立邮件并更新基线。
- 稳定指标、实时指标、加速观察计数是三套相关状态；如果实现混用锚点，可能重复告警或错误暂停。
- SQLCipher 默认格式与口令模式有官方依据，但实际驱动包、DBX 客户端版本、轮换后重开及跨平台备份互操作尚未实测。
- `.env` 允许无人值守启动，但根密钥以明文文件存在于应用根目录；操作系统权限、备份、轮换原子性和丢失后的恢复责任必须写清。
- 用户自行取得活动数据库文件时可能漏掉 WAL 或得到不一致副本；交付说明必须要求停写或使用一致性备份机制。
- usage 的 requests/tokens 字段、分页、Token 失效和暂停 PUT 成功响应需脱敏样例确认。
- 开发若直接复用关联项目 pipeline/store 的旧 `estimated_total_quota` 会产生错误口径；只能复用接口字段与认证经验，指标必须按本 PRD 重新实现。
- 原始缓存满且全部文件未抽取时不能删除待处理数据，需要明确背压和恢复行为。
