# 测试计划

> 对应 PRD 1.3-draft，已吸收 README 和本轮逐项确认规则。当前没有实现代码、依赖清单或测试命令。以下是需求批准后应建立的验证范围；待确认场景必须先定稿预期值，本轮未运行产品测试。

## 1. 单元测试

- utilization 百分数边界：0、1、57、99、100、负值、超过 100、缺失和非数字；确认 57 到 58 是一个百分点。
- 四指标公式：平台期逐样本两个实时指标；基线重置后第二次及以后 utilization 增加时，稳定 cost=`cost/(utilization-1)*100`，稳定 delta=`两次跳变 cost 差/实际 utilization 差*100`。验证 utilization 为 0、分母无效、字段缺失和结构化不可计算原因。
- 数值样例：`cost=318.24, utilization=16` 的实时 cost 为 1989；跳变至 `18%/cost=360` 时稳定 cost 约 2117.65；前跳变为 `16%/cost=318` 时稳定 delta 为 2100，并标记跨 2 个百分点。
- 实时 delta：初始/重置基准 `16%/cost=318`，平台期 `16%/cost=320` 得 200；跳变 `18%/cost=360` 仍用旧基准得 2100，随后才更新基准。基线当条不可计算，与真实计算结果 0 区分。
- 跳变边界：相同 utilization 不生成稳定值；+1 与跨多个百分点都算一次变化，首次变化只建起点、第二次开始稳定计算；跨多百分点继续告警/暂停且低精度提示贯穿页面、邮件和审计。
- 启动/回退代次：首次启动、重启、utilization 回退或原始 cost 下降统一重建基线；基线记录不触发稳定指标邮件或自动暂停。utilization 持续为 0 而 cost 再下降时发独立 cost 异常邮件并更新基线，本条实时 delta 不可计算。
- 趋势分类：首个稳定 cost 仅与生效 low 严格比较，低于 low 发 cost 邮件并加速、但不单凭 cost 自动暂停；后续只按相邻稳定 cost 下降比例判断，恰好下降 5% 不触发。
- delta 档位：high > medium > low 校验、四档边界、不可计算跳过和稳定 `delta < low` 自动暂停判定；实时 delta 不触发。
- 全局自动暂停关闭时抑制动作但保留账户暂停偏好与生效预设；全局重新开启后账户偏好恢复生效。
- 加速观察状态：触发 cost 事件的跳变不计数，后续第一跳建立观察起点、第二跳完成区间；计算锚点与观察计数互不覆盖。
- cost/delta 独立事件、普通/告警间隔和各自去重；cost 稳定值严格上升只恢复 cost 事件，稳定 delta > medium 只恢复 delta 事件。
- 同一跳变同时命中稳定 cost 与 delta 时生成两个独立事件，但只投递一封标明“多合一提醒”的邮件；两个事件均关联该投递，平台期快速采样不重复发送。
- 数据异常矩阵：回退到 0/非 0 × cost 下降/不下降；非零回退且 cost 下降发**一封合并邮件**，列两个旧/新值；刚从非零回退到 0 发一封可能重置提醒，伴随下降不另发一般 cost 下降邮件；后续 `0→0、cost 80→40` 则发独立 cost 下降邮件并使高残留事件恢复。当前记录只重建一次基线。
- 回退记录不进入稳定额度指标判断；同一条无原始回退的正常跳变上，稳定 cost 与稳定 delta 各自判定事件，邮件合并。重启首条建立新基线，不与上次运行末条比较或补发回退提醒；只观察到非零 utilization 回退时一律判异常，不推测采样错过 0。
- 同条邮件候选先按三类数据异常开关和账户三态过滤：0 项不发、1 项发普通邮件、2 项以上只发一封“多合一提醒”。验证 `U:16→0、C:350→80、high=3000` 同条可能重置与高残留合并；任一规则关闭时仅含开启项，两个都关闭时无邮件。审计仍保存原始规则命中。
- 零利用率残留：默认 `3000*0.01*2=60`，cost 恰好 60 不触发、超过 60 触发；首次采样与回退到 0 使用不同邮件模板，共享开关。账户生效 high 覆盖全局 high。
- 三类数据异常邮件各有默认开启的全局开关和账户继承/开启/关闭；全局关闭抑制发送但不重置账户设置。连续新的回退/一般 cost 下降各可产生新事件；零利用率高 cost 持续超阈仅发一封，cost 回到生效阈值内或 utilization 离开 0 后再越阈才重发；同一采集重试不得重复发信。
- 预设库：创建/命名/编辑多套 high>medium>low；全局一套、账户一套或继承；切换/编辑从下一成功采样生效，历史规则与邮件阈值快照不变。
- 预设删除与批量修改：全局引用禁止删除；仅账户引用时确认并使受影响账户继承全局。筛选使用指定预设的账户，单项批改不碰其他项；多项依赖有序、独立项分开、失败整批回滚。
- cost 事件提前恢复、自动暂停成功或观察窗口完成时恢复普通间隔；长期没有有效跳变时保持当前间隔并显示等待，不执行未配置的超时退出。
- 原始文件名清洗、原子写入、保留天数、最大缓存字节数和最老已抽取文件清理排序。
- 十六进制密钥格式：16 个随机字节、32 个 hex 字符、首次写入应用根目录 `.env`、重启不覆盖、独立版本；数据库端将 32 字符按文本口令输入。误当原始密钥、口令格式改变必须被验证发现。

## 2. 接口和集成测试

- 多租户、每租户多个管理账号的登录、Token 隔离、401、过期重登和认证错误定位。
- 账号列表分页、`platform=openai` 过滤、同号 account_id 跨租户隔离和已失效账号保留历史。
- usage 的完整 envelope 原始落盘、seven_day 解析、未知字段、requests/tokens 实际路径、解析失败和重试。
- `source=local`、配置时区、请求超时、网络失败和业务错误的日志分类。
- 暂停/恢复 PUT 成功、超时、非 2xx、业务失败、重复请求、结果未知和重试；只有成功响应才更新状态。
- SQLCipher 绑定/核心版本、v4 默认格式、文本口令、初始化、事务、轮换与 Windows/Linux 打包；不能误链接普通 SQLite 后假装已经加密。
- SMTP TLS、认证失败、发送超时、重试、收件人继承/覆盖、稳定 cost/delta 与三类数据异常模板区分、同采集投递幂等。

## 3. 数据和恢复测试

- 加密 SQLite 初始化、迁移、事务回滚、单写并发和幂等写入。
- 服务重启后恢复 queued、etl_pending、failed 和历史告警记录；新启动代次的首条成功采样建立基线，首次后续利用率变化只建稳定计算起点，不沿用上代次旧锚点进行告警。
- 原始文件写入中断、磁盘不足、文件占用、缓存超限和全部文件未抽取时的背压。
- 数据库密钥轮换成功、失败恢复、重启续作、`.env` 原子替换和匹配密钥备份恢复；模拟数据已切换但 `.env` 未切换及反向不一致，均必须回滚或进入可恢复维护态。
- 机密信息密钥独立轮换后旧记录可读、新写入使用新密钥、轮换失败不产生半轮换。
- 轮换期间原始 JSON 持续落盘、ETL 暂停；轮换后按时间补偿且不重复采样。
- 多租户备份恢复不串 Token、account_id、收件人或暂停目标。

## 4. 浏览器和手工验收

- Windows 与 Linux 首次登录强制改密、默认密码安全提示、改账号前重新验证。
- 多租户/管理账号连接页、OpenAI 账号筛选、账号列表和详情的正常/空/加载/错误/无权限状态。
- 平台期、跨百分点跳变、回退重置的四指标展示、低精度提示、稳定值时间、独立事件恢复锁和 Pixel 暂停状态。
- 命名预设库、全局/账户选择、按所用预设筛选、批量修改预览与失败回滚；删除账户引用预设前显示受影响账户数。
- 回退邮件、cost 下降邮件、首次零利用率 cost 过高与回退残留邮件的不同文案和三态开关。
- 管理账号默认收件人、监控账号覆盖、测试邮件和最近发送结果。
- 危险操作确认、两个密钥分别验证/查看/轮换、`.env` 加载/权限错误、数据库维护状态和进度。
- 原始缓存保留天数、最大字节数、当前用量、积压和清理失败状态。
- Windows 单 `.exe` 在干净目录启动、重启、替换可执行文件后数据保留与恢复。
- 首版仅一个可直接点击的 `.exe`：首次运行在同目录生成 `.env` 与加密数据库，所有其他设置可在 Web 修改并持久化；重启不覆盖原文件。Linux 版也从程序文件所在目录读写 `.env` 与数据库，即使服务当前工作目录不同；Web/数据库配置流程相同。
- Linux x86_64 版只交付一个应用可执行文件：在干净目标机上检查 Web 资源和 SQLCipher 加密组件可用，不需要额外复制项目专用 `.so`；首次运行同目录生成 `.env`/加密数据库，Nginx 反代访问正常。系统运行库兼容性按最终发行版验证。

## 5. 安全测试

- 密码哈希不可逆，首次默认密码登录不能进入业务页；初始化后再次出现默认密码时必须提示，是否同样阻断按 PRD 11.2 的评审结果验证。密码校验材料和可逆机密按批准密钥方案保护。
- 日志、一般页面、错误响应、原始文件下载和备份中不泄露 Token、密码、SMTP 凭据和完整密钥；密钥专用查看页仅在当次重新验证后短时显示。
- 会话 Cookie、CSRF、登录失败限制、退出失效和操作级重新验证。
- 租户隔离、越权访问、路径遍历、任意文件下载、配置注入和原始 JSON 下载权限。
- 数据库口令只允许出现在受限权限的应用根目录 `.env` 和进程环境，不出现在命令日志、进程参数、错误响应或其他明文配置中；正确数据库口令不应解开第二密钥保护的应用层字段。
- Web 静态文件、下载接口、路径遍历和备份接口均不能读取 `.env`；产品不得监听数据库远程端口或提供 SSH 隧道配置。
- 密钥轮换和后台任务不能被未授权请求触发。

## 6. 性能和发布冒烟

- 多租户、多账号在一个采样周期内完成调度；单账号慢请求不阻塞其他账号。
- 原始缓存接近字节上限时清理耗时、磁盘使用和背压可控。
- 轮换期间持续采集不会造成未受控的内存增长，ETL 能在维护后补偿。
- 应用及所选数据库组件在没有 Go 工具链的 Windows 测试环境中能启动、重启和恢复；Linux 目标包在实现阶段按所选运行时验证。
- 发布前执行一次真实 Pixel 测试账号端到端采样；测试凭据只通过运行时注入，测试后撤销或轮换。

## 7. 评审前阻塞项

以下不是测试失败，而是需要产品/架构定稿后才能编写稳定断言的内容：

- PRD R2：`.env` 权限、备份/恢复责任及不提供 Web 下载的边界。
- PRD R3：后端语言及 Linux 发行版/版本、运行账号和程序部署位置；Linux x86_64 单可执行文件、操作系统负责开机启动/异常拉起、Windows 单 `.exe`、两端程序同目录 `.env`/数据库已确认。
- 脱敏 usage、账号列表、认证失败和 PUT 响应样例。


## 8. 第三方客户端兼容性验收

以下用例是后续实现验收，不是本轮实测结果。默认针对 DBX 本地文件连接，并用带 SQLCipher 支持的 DB Browser 交叉验证；官方支持依据见 ARCHITECTURE.md 第 9 节。

| 编号 | 操作 | 预期 |
|---|---|---|
| COMPAT-01 | 应用按 SQLCipher 4 默认格式创建测试库，退出写入后在 DBX 本地连接输入数据库口令 | 可读表结构和普通业务行，无需导出明文；记录应用、核心、绑定和 DBX 版本 |
| COMPAT-02 | 同一库在 SQLCipher 版 DB Browser 以 v4 默认参数和同一口令打开 | 与应用、DBX 读取的样本数及值一致 |
| COMPAT-03 | 使用错误口令、空口令及不支持加密的普通 SQLite 连接读取 | 不能读取真实表；失败不得覆盖/重建现有文件 |
| COMPAT-04 | 应用轮换数据库口令，关闭旧连接后用 DBX 重新连接 | 新口令可读，旧口令不能打开轮换后的文件；旧备份仍按其原口令管理 |
| COMPAT-05 | 仅轮换应用层机密信息密钥，再用 DBX 打开库 | 数据库口令不变，普通字段可读，机密字段仍为密文，应用可正常解密 |
| COMPAT-06 | Linux 在停写或经验证的一致性备份机制下生成加密文件，再复制到 Windows 本地打开 | 无需明文中间库即可读取；不遗漏 WAL 数据；直接复制活动主文件不能作为通过证据 |
| COMPAT-07 | 如果改用 SQLite3 Multiple Ciphers 等替代引擎 | 显式匹配 SQLCipher 4 格式，重复 COMPAT-01 至 06；库名或相同 AES 算法不视为通过 |
| COMPAT-08 | 检查部署端口、页面和配置 | 只暴露批准的 Web 服务；不存在产品提供的 SSH 隧道、远程数据库监听或 DBX 远程连接入口 |

默认只读检查副本；外部工具对业务库写入、改表或改口令不纳入本期常规运维流程，避免绕过应用审计和轮换协调。
